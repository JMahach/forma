# Бодиграф

Локальный сайт для расчёта и исследования бодиграфа. Дата, время и город рождения превращаются в активации ворот; схему можно приближать, перемещать и разбирать касанием. Код, движок расчёта и справочники лежат в этом проекте. Публичный хостинг не нужен.

## Запуск на Mac / Linux

Нужны Node.js 20+ и Python 3.9+. В подготовленной копии проекта окружение `.venv` уже установлено; для неё достаточно `npm start`. На новом компьютере выполните из папки проекта:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm start
```

Откройте [сайт на этом компьютере](http://127.0.0.1:4173). Npm-зависимостей нет, сборка фронтенда не требуется. Python-зависимости закреплены в `requirements.txt`: `pyswisseph==2.10.3.2` и `tzdata==2026.3`. Первая установка требует загрузки пакетов; последующие расчёты и поиск городов работают без внешних запросов.

Локально должны находиться `data/cities.json`, `data/ephe/sepl_18.se1` и `data/ephe/semo_18.se1`. Они включены в подготовленный проект. `.venv` не следует переносить между компьютерами — создайте окружение заново командами выше. Если для вашей версии Python нет готового пакета `pyswisseph`, установка может потребовать инструменты компиляции.

Для телефона или iPad в той же доверенной Wi-Fi-сети остановите обычный сервер и запустите:

```sh
HOST=0.0.0.0 npm start
```

На устройстве откройте `http://<локальный-IP-компьютера>:4173`. Компьютер должен оставаться включённым. Этот режим открывает сайт участникам локальной сети; по умолчанию сервер слушает только `127.0.0.1`. Регистрации, авторизации и HTTPS в локальном сервере нет. Публикация в интернете отдельно не настроена.

## Создание и исследование карт

- **«＋» — карта рождения.** Введите имя, местные дату и время рождения, затем выберите город из списка. Можно вводить `12091990` и `1430`: разделители добавятся сами. Город определяет исторический часовой пояс, а не текущее смещение на вашем устройстве.
- **Перевод часов.** Для времени, которое повторялось дважды, появится выбор смещения. Несуществовавшее местное время не рассчитывается: нужно уточнить исходные данные.
- **«Сейчас» — текущий момент.** Открывается при каждом заходе на сайт и пересчитывает реальные положения планет каждую секунду по часам компьютера-сервера. Обновление работает только для видимой карты текущего момента и приостанавливается при скрытии вкладки или открытии формы рождения. Одна запись в библиотеке сохраняется раз в 30 секунд, без накопления истории. Подзаголовок показывает время в часовом поясе браузера; масштаб схемы сохраняется.
- **«Ввести вручную».** Позволяет записать известные активации без астрономического расчёта. Такие карты помечены как ручные. Демонстрационная карта остаётся явно обозначенным учебным примером.
- **Значок меню слева.** Открывает библиотеку, создание карты, редактирование, импорт и экспорт. Редактирование рассчитанной карты выполняет новый расчёт; экспорт и импорт переносят карту в JSON.
- **Удаление.** Откройте сохранённую карту, затем меню → «Удалить карту». После подтверждения она убирается из библиотеки, но сохраняется в локальной корзине. «Вернуть удалённую карту» восстанавливает последнюю удалённую запись, в том числе после перезагрузки страницы; повторное нажатие возвращает предыдущую. Демонстрация и текущий момент не удаляются. Это не стирание личных данных: копия остаётся в этом браузере до очистки данных сайта. В корзине можно хранить до 500 карт.

Схема содержит 9 центров, 64 ворот и 36 логических каналов. Подсветка показывает связи, полные каналы определяют центры. Карточки и библиотека открываются поверх схемы, не сдвигая её. Масштаб и положение запоминаются отдельно для каждой карты. Для клавиатуры доступны Tab, Enter и пробел.

## Как устроен расчёт

Движок — Swiss Ephemeris `2.10.03` через Python-обёртку `pyswisseph 2.10.3.2`. Используются локальные Swiss-файлы эфемерид; в заголовках включённых файлов указана база **JPL DE441**. Отсутствие нужных файлов завершает расчёт ошибкой: автоматический переход на приближённую модель Moshier запрещён.

Вычисляются тропические геоцентрические видимые долготы Солнца, Луны, планет и истинного северного узла (**true node**). Земля и южный узел берутся напротив Солнца и северного узла. Долготы сопоставляются с 64 воротами и шестью линиями. Для дизайна ищется момент до рождения, когда долгота Солнца отстаёт на 88°, а не просто дата за 88 суток. Для текущего момента вычисляется только один набор положений; натальный дизайн ему не приписывается.

В рассчитанной карте сохраняются исходные местные дата и время, выбранный город и его идентификатор, часовой пояс, UTC и смещение, выбор повторившегося времени, момент дизайна, долготы/ворота/линии для каждого объекта, версии движка и базы часовых поясов, а также численный остаток поиска 88°. Сохранённый экспорт позволяет проверить, из каких данных получилась карта.

## Ограничения и проверка точности

Поддерживаются даты рождения **с 1801 по 2399 год включительно**, по григорианскому календарю. Это рабочий диапазон приложения, а не обещание одинаковой исторической достоверности для всех дат.

Часовые пояса берутся из закреплённого пакета IANA `tzdata 2026.3`, независимо от базы операционной системы. Сведения до 1970 года местами неполны, а будущие правила могут измениться. Для старых записей особенно важно проверить календарь, местные правила времени и точность самой записи рождения. Идентификатор часового пояса города не решает все исторические исключения. Подробнее — [ограничения базы IANA](https://data.iana.org/time-zones/tzdb/theory.html#accuracy).

Принята конвенция истинного, а не среднего лунного узла. Регрессионные проверки астрономического движка, границ ворот/линий и часовых поясов выполнены; один публичный пример из [проверочного набора DefinedSelf](https://definedself.com/data#verification-battery) совпал по всем 26 парам «ворота.линия». **Независимая проверка на официальных эталонах Jovian Archive и расширенном наборе карт ещё предстоит.** Значение `designArcResidualDegrees` характеризует сходимость численного поиска, а не общую точность карты и не достоверность исходного времени. Особенно чувствительны положения рядом с границами ворот и линий.

Автоматические тип, авторитет и профиль пока не выводятся. Пользовательская база знаний, синхронизация, регистрация и платежи не подключены. Описания — формулировки внутри системы Human Design, не медицинские или психологические заключения.

## Локальные данные и приватность

Браузер отправляет запрос города и данные для расчёта **только вашему локальному серверу**. Сервер читает локальные справочники и запускает локальный Python-процесс; к внешним калькуляторам данные не передаются. Он не записывает библиотеку карт на диск и не журналирует данные рождения. В проекте нет внешних шрифтов, аналитики или CDN.

Библиотека хранится в `localStorage` конкретного браузера и адреса сайта. На Mac и iPad, а также при открытии через разные адреса сервера это отдельные библиотеки. Очистка данных браузера удалит карты; сделайте экспорт важных записей. JSON содержит имя, данные рождения, заметки и расчётные метаданные в читаемом виде — это не зашифрованная резервная копия. Импорт/экспорт не отправляет файл внешним сервисам.

## Структура проекта

- `index.html`, `styles.css` — минимальный адаптивный интерфейс.
- `app.js`, `date-input.js` — формы, подсказки городов, вызовы локального расчёта и библиотека.
- `graph-data.js`, `bodygraph.js` — топология, оригинальная геометрия и SVG.
- `gestures.js` — масштабирование и перемещение.
- `storage.js` — проверка и перенос карт, включая расчётные метаданные.
- `server.mjs` — локальный сервер: `/api/cities`, `/api/calculate` и явный список ресурсов сайта.
- `calculator.py`, `requirements.txt` — расчёт и закреплённые Python-зависимости.
- `data/cities.json`, `data/ephe/` — локальный справочник городов и эфемериды.
- `THIRD_PARTY.md` — происхождение и лицензии сторонних компонентов.

Сервер не выдаёт через HTTP файлы Git, Python-окружение, исходные файлы расчёта или произвольные файлы проекта.

## Тесты

```sh
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

JavaScript-тесты проверяют топологию, SVG, жесты, даты и перенос карт. Python-тесты — часовые пояса, неоднозначное и несуществующее время, диапазон дат, границы ворот/линий, расчёт дизайна и работу с реальными эфемеридами. Эти проверки не заменяют независимую валидацию полной Human Design-карты. Жесты на реальном iPad требуют проверки на устройстве.

Проверки HTTP API по умолчанию пропускаются. Чтобы включить их, сначала запустите `npm start`, затем в другом терминале выполните:

```sh
RUN_API_TESTS=1 npm test
```

Они обращаются только к локальному серверу и проверяют подсказки городов, расчёт, переходы времени и границы доступа к файлам. Другой адрес задаётся через `API_TEST_BASE_URL`.
