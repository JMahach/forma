# Форма

«Форма» рассчитывает карту Human Design по дате, времени и городу рождения и показывает её как бодиграф или мандалу. Рисунок можно приближать, двигать, выделять его части и рассматривать изменения в течение дня.

Этот README объясняет, **как действие человека проходит через проект: где берутся данные, кто их хранит и что меняется на экране**.

## Сначала разделим три вещи

- **Карта** — данные: момент времени, положения планет, ворота и линии. Сохранённая карта рождения лежит в библиотеке.
- **То, что сейчас показано** — сохранённая карта, текущий транзит или временная минута выбранного дня. Просмотр другой минуты не переписывает карту в библиотеке.
- **Рисунок на экране** — отображение этих данных. Масштаб, положение, подсветка и открытые панели относятся к просмотру, а не к расчёту рождения.

Например, можно приблизить карту, выделить ворота и передвинуть шкалу дня. Это три разных действия: меняются камера, выбор и временная минута. Сохранённая карта остаётся прежней.

## Где работает каждая часть

| Часть | За что отвечает |
| --- | --- |
| Браузер: `src/` и `public/` | Принимает действия человека, хранит его библиотеку, выбирает показанные данные и обновляет рисунок. |
| Сервер Node: `server/` | Принимает запросы, ищет города, управляет очередями расчёта и кэшами, отдаёт данные и файлы сайта. |
| Расчёт Python: `server/python/` | Уточняет момент UTC, получает положения планет через Swiss Ephemeris и готовит данные карты или дня. |
| Общий формат: `shared/day-packets/` | Объясняет серверу и браузеру, как записывать и читать числовые пакеты дня. |

Запуск начинается в [src/startup.js](src/startup.js): он сразу запрашивает текущий день и загружает интерфейс. Затем передаёт того же получателя данных в [src/app.js](src/app.js). Этот файл создаёт части приложения и связывает их: «получили карту — обнови страницу», «выбрали ворота — обнови рисунок». Сами правила расчёта, хранения и движения находятся в своих модулях.

За запросы и кэш отвечает `data/transit-day-client.js`, за выбранную минуту, повтор после ошибки и остановку работы в скрытой вкладке — `state/live-transit.js`. Ранний запуск не создаёт вторую копию этих правил или второй запрос того же дня.

## Что происходит при обычных действиях

### Ввёл дату, время и город — получил карту

1. [views/birth-form.js](src/views/birth-form.js) читает форму. Город выбирается из результатов `/api/cities` вместе с его идентификатором.
2. Форма отправляет данные через [data/api-client.js](src/data/api-client.js) в `/api/calculate`.
3. [server/http/app.mjs](server/http/app.mjs) направляет запрос в [services/calculate.mjs](server/services/calculate.mjs). Общий [runtime/json-worker.mjs](server/runtime/json-worker.mjs) запускает Python и получает его JSON-ответ.
4. [calculator.py](server/python/calculator.py) соединяет перевод времени из [civil_time.py](server/python/civil_time.py) и астрономию из [astronomy.py](server/python/astronomy.py).
5. Форма передаёт готовую запись в [data/chart-store.js](src/data/chart-store.js). [state/chart-session.js](src/state/chart-session.js) выбирает её для показа, после чего обновляются подпись, библиотека и рисунок.

Для ручной карты человек задаёт ворота сам: астрономический расчёт в этом случае не нужен.

### Открыл карту из библиотеки

[views/library.js](src/views/library.js) сообщает идентификатор выбранной записи. [scene/updates.js](src/scene/updates.js) сбрасывает прежнее выделение, а [state/chart-session.js](src/state/chart-session.js) меняет выбранную карту и завершает временный просмотр дня. Данные уже лежат в библиотеке; повторно рассчитывать рождение не требуется.

### Передвинул шкалу дня

У проекта две шкалы с общей идеей: **сначала получить пакет чисел для дня, затем выбирать из него минуту в браузере**.

| Шкала | Кто хранит минуту | Кто получает пакет | Кто превращает минуту в карту |
| --- | --- | --- | --- |
| Текущий транзит | [state/live-transit.js](src/state/live-transit.js) | [data/transit-day-client.js](src/data/transit-day-client.js) | [domain/transit-day.js](src/domain/transit-day.js) |
| День рождения выбранной карты | [state/natal-day.js](src/state/natal-day.js) | [data/natal-day-client.js](src/data/natal-day-client.js) | [domain/natal-day.js](src/domain/natal-day.js) |

Путь изменения: **ползунок → контроллер дня → временная карта → сессия → рисунок**. Сессия выбирает источник показанной карты; она не копирует библиотеку внутрь контроллера дня.

Каждое полученное положение ползунка обрабатывается по порядку. Планеты обновляются и тогда, когда их угол изменился совсем немного, а ворота и линия остались прежними. Одинаковая уже показанная минута может быть пропущена. Запрос на сервер при каждом движении ползунка не отправляется.

Контроллер транзита сравнивает выбранный момент с уже показанным до сборки новой карты. В дне рождения `domain/natal-day.js` переводит номер минуты в момент UTC; текст даты появляется только там, где он нужен для показа. `state/natal-day.js` один раз находит исходную минуту рождения и хранит её как точку возврата. Ползунок читает эту точку из состояния, а не вычисляет её заново.

В транзите движение шкалы выключает следование за часами; кнопка «Сейчас» включает его обратно. В дне рождения сброс или закрытие шкалы возвращает точную исходную карту. Ответ от старого запроса не должен подменять новую выбранную карту: контроллеры проверяют, к какой загрузке относится результат.

### Нажал на ворота, канал или центр

[scene/gestures.js](src/scene/gestures.js) отличает нажатие от перетаскивания и передаёт выбранный объект в [scene/updates.js](src/scene/updates.js). Тот меняет [selection/selection-model.js](src/selection/selection-model.js) и просит обновить рисунок и связанные панели.

У выбора три связанных уровня:

- [selection-state.js](src/selection/selection-state.js) — обычные выбранные объекты и добавление через Shift;
- [summary-selection-state.js](src/selection/summary-selection-state.js) — группы ворот, выбранные через строки сводки;
- [selection-model.js](src/selection/selection-model.js) — общий выбор, включая закреплённые кресты мандалы и пересечение групп.

Наведение принадлежит отдельному [hover-preview.js](src/selection/hover-preview.js). Оно даёт временную подсветку и не заменяет закреплённый выбор. [selection-targets.js](src/selection/selection-targets.js) определяет, какие ворота относятся к объекту; отрисовщикам не нужно придумывать это заново.

### Приблизил или передвинул рисунок

Путь движения: **палец → `gestures.js` → `camera.js` → `camera-view.js` → положение SVG**.

- [gestures.js](src/scene/gestures.js) разбирает касания, колесо и клавиши. После начала перетаскивания учитывает весь путь от первого касания, включая движение внутри допуска на нажатие.
- [camera.js](src/scene/camera.js) хранит три числа: `x` и `y` — сдвиг, `k` — масштаб. Здесь же находятся границы движения, исходное положение Home и возврат к нему.
- [camera-view.js](src/scene/camera-view.js) переводит экранные координаты в координаты рисунка и применяет CSS-преобразование ко всему SVG.

Неподвижный `canvasWrap` принимает жесты и задаёт размеры поля. Внутри него движется `bodygraph` — сам SVG. Поэтому перемещение рисунка не перемещает «линейку», которой измеряется следующий шаг пальца.

Каждое событие сразу меняет численное положение камеры. Несколько событий до ближайшего кадра объединяются в одну запись положения на экран. При отпускании пальца учитывается и последняя координата, если она ещё не приходила в событии движения, после чего положение применяется сразу. Отмена жеста сохраняет последнее корректное положение. Правило обновления шкалы дня от этого не меняется.

### Включил мандалу

[scene/modes/mandala.js](src/scene/modes/mandala.js) хранит, включён ли режим. [mandala-motion.js](src/scene/modes/mandala-motion.js) ведёт визуальный переход. Карта и закреплённый выбор остаются прежними; добавляется кольцо и меняется представление рисунка. При выключении кольцо сначала перестаёт принимать выбор, затем убирается после затухания.

Лотос — единственная подложка бодиграфа, отдельного переключателя или состояния лотоса нет. Его форма находится в [geometry/lotus-backdrop.js](src/scene/geometry/lotus-backdrop.js), оформление — в [scene/backdrop.js](src/scene/backdrop.js).

## Кто хранит состояние

Состояние — то, что приложение должно помнить между двумя действиями: например, выбранную карту или положение камеры.

| Что помним | Единственный владелец | Когда меняется и сколько живёт |
| --- | --- | --- |
| Сохранённые карты | [data/chart-store.js](src/data/chart-store.js) | При сохранении, редактировании и удалении. [storage.js](src/data/storage.js) проверяет прочитанные записи и записывает библиотеку в `localStorage` этого сайта. |
| Какую карту показывать | [state/chart-session.js](src/state/chart-session.js) | При выборе записи или транзита. Выбирает между оригиналом и временной картой дня; живёт в открытой странице. |
| Транзит: минута, «Сейчас», готовность загрузки | [state/live-transit.js](src/state/live-transit.js) | От часов, ползунка и загрузки пакетов. Это временное состояние, не запись библиотеки. |
| День рождения: оригинал, временная минута, открытая шкала | [state/natal-day.js](src/state/natal-day.js) | При выборе карты и работе со шкалой. Закрытие возвращает оригинал. |
| Закреплённое выделение | [selection/selection-model.js](src/selection/selection-model.js) | От нажатий, Shift и сводки. Сброс или смена карты очищает выбор. |
| Временное наведение | [selection/hover-preview.js](src/selection/hover-preview.js) | Пока указатель или фокус показывают объект. Хранится отдельно от закреплённого выбора. |
| Сдвиг, масштаб и Home | [scene/camera.js](src/scene/camera.js) | От жестов, Home и изменения размеров экрана. Не записывается в карту. |
| Режим мандалы и его переход | [scene/modes/mandala.js](src/scene/modes/mandala.js), [mandala-motion.js](src/scene/modes/mandala-motion.js) | Первый хранит выбранный режим, второй — ход анимации. |
| Открытые меню, форма и панели | Соответствующие модули в [views/](src/views/) | Каждый управляет своим интерфейсом; `app.js` связывает действия, например закрытие библиотеки при открытии сводки. |

Библиотека, временный просмотр, выбор и камера имеют разных владельцев, потому что меняются независимо. [scene/render-state.js](src/scene/render-state.js) получает уже выбранную карту, выделение и параметры показа и готовит данные для одного обновления рисунка. Он не хранит библиотеку или камеру и не становится новым хранилищем карты.

## Как рисунок обновляется без лишней работы

До получения данных виден пустой контур карты и нейтральные строки вместо чисел. Начальная страница открывает транзит: у его заглушки только правый столбец. В рассчитанной личной карте показываются оба столбца — дизайн и личность. [scene/loading-placeholder.js](src/scene/loading-placeholder.js) берёт существующую геометрию и готовит SVG для исходного HTML на сервере или при сборке. Браузеру не нужно ждать запуска приложения, чтобы показать его. Это неподвижная иллюстрация; камера настоящей карты ею не управляет. [views/chart-loading.js](src/views/chart-loading.js) убирает заглушку, когда сессия уже имеет карту, и показывает повтор при ошибке. Готовая карта не ждёт догрузки всей шкалы дня. До появления данных центры остаются пустыми, без выдуманных чисел и цветов.

[scene/updates.js](src/scene/updates.js) решает, какие данные и выделение показать. [scene/renderer.js](src/scene/renderer.js) создаёт SVG-основу, затем сохраняет её и обновляет существующие элементы.

| Часть рисунка | Первое создание | Последующие изменения |
| --- | --- | --- |
| Центры, каналы, ворота | [bodygraph-svg.js](src/scene/bodygraph-svg.js) | [bodygraph-painter.js](src/scene/bodygraph-painter.js) |
| Кольцо и планеты мандалы | [mandala.js](src/scene/mandala.js) | [mandala-painter.js](src/scene/mandala-painter.js) |
| Колонки активаций | [activation-columns.js](src/scene/activation-columns.js) | [activation-painter.js](src/scene/activation-painter.js) |

Правила цвета и подсветки общие для создания и обновления: [bodygraph-paint.js](src/scene/bodygraph-paint.js) и [mandala-paint-rules.js](src/scene/mandala-paint-rules.js).

Стрелки рассчитывает [domain/variables.js](src/domain/variables.js). Отрисовщик сравнивает их готовое описание и обращается к [variable-arrows.js](src/scene/variable-arrows.js) за новой разметкой только при изменении стрелок. В бодиграфе маска выбранного пути и маски подсветки каналов обновляются отдельно: смена выделения не пересобирает неизменные маски каналов. Маска здесь — трафарет, который ограничивает видимую часть подсветки.

Точки и лучи креста готовит [geometry/mandala-geometry.js](src/scene/geometry/mandala-geometry.js). И первое создание креста, и его движение используют эти координаты. Новая SVG-разметка нужна только при создании или изменении состава креста; обычное движение обновляет существующие отметки.

При движении шкалы точные положения планет обновляются каждый раз. Сектора мандалы пропускают повторную обработку, если их ворота, выделение и доступность не изменились. Расстановка подписей планет зависит от их точных координат: простое выделение её не пересчитывает, а любое изменение координат пересчитывает. Эти сведения о нарисованном хранятся внутри `mandala-painter.js` и сбрасываются вместе с рисунком. При обычном перемещении камеры меняется положение всего SVG, а карта не пересчитывается и фигуры не создаются заново.

[views/chart-display.js](src/views/chart-display.js) готовит название и дату карты. [chart-heading-layout.js](src/views/chart-heading-layout.js) записывает только изменившиеся подписи и размещает их между кнопками. Размер окна и загрузка шрифта проверяются отдельно, даже если текст остался прежним.

Счётчик из [diagnostics/frame-monitor.js](src/diagnostics/frame-monitor.js) наблюдает интервалы браузерных кадров. [views/performance-monitor.js](src/views/performance-monitor.js) показывает результат. Счётчик не управляет камерой; его FPS — оценка по кадровым вызовам браузера, не аппаратное измерение показанных экраном кадров.

## Где менять форму, размеры и движение

| Нужно изменить | Где это правило |
| --- | --- |
| Форму центра, путь канала, положение ворот | [scene/geometry/](src/scene/geometry/) — геометрия в координатах рисунка. |
| Положение столбцов активаций, заголовков и расстояние между строками | [geometry/activation-layout.js](src/scene/geometry/activation-layout.js). Одна настройка используется готовой картой и заглушкой загрузки; внешние границы столбцов для размещения на экране вычисляются из неё. |
| Кольцо, секторы и круговую разметку | [geometry/mandala-geometry.js](src/scene/geometry/mandala-geometry.js). |

| Отступы от кнопок и шкалы, размещение на телефоне | [scene/layout.js](src/scene/layout.js) считает размещение; [studio-controller.js](src/scene/studio-controller.js) читает размеры страницы и применяет результат. |
| Пределы приближения и сдвига | [scene/camera.js](src/scene/camera.js). |
| Перевод экранных координат и перемещение SVG | [scene/camera-view.js](src/scene/camera-view.js). |
| Цвета, шрифты, внешний вид кнопок и панелей | [public/styles.css](public/styles.css). |

Так разделены три разных вопроса: **какой формы рисунок; как он помещается в окно; куда пользователь его передвинул**.

## Где считается математика карты

| Расчёт | Смысл | Владелец |
| --- | --- | --- |
| Местное время → UTC | Учитывает пояс города и неоднозначное время при переводе часов. | [server/python/civil_time.py](server/python/civil_time.py) |
| Положения планет | Получает долготы через Swiss Ephemeris; Земля и Южный узел находятся напротив Солнца и Северного узла. | [server/python/astronomy.py](server/python/astronomy.py) |
| Момент Дизайна | Ищет более ранний момент с отставанием Солнца на 88°. Это угол, а не 88 суток. | [server/python/astronomy.py](server/python/astronomy.py) |
| Долгота → ворота и линия | Круг делится на 64 сектора по 5,625°, каждый — на 6 линий. Порядок номеров ворот задан таблицей. | [domain/gate-wheel.js](src/domain/gate-wheel.js); соответствующее серверное правило — `astronomy.py` |
| Цвет, тон, база | Линия делится на 6 цветов, цвет — на 6 тонов, тон — на 5 баз. | [domain/substructure.js](src/domain/substructure.js) |
| Направления четырёх пар стрелок | Выбираются по цветам и тонам соответствующих активаций. | [domain/variables.js](src/domain/variables.js) |
| Каналы и определённые центры | Активные ворота соединяются по таблице каналов; оба активных конца дают полный канал. | [domain/topology.js](src/domain/topology.js) |
| Профиль и сводные сведения | Читаются и объединяются данные активаций карты. | [domain/chart-facts.js](src/domain/chart-facts.js) |
| Фиксация линий | Активации сопоставляются с таблицей правил. | [domain/line-fixing.js](src/domain/line-fixing.js), [line-fixing-data.js](src/domain/line-fixing-data.js) |
| Крест мандалы | Угол задаёт четыре позиции на круге и соответствующие ворота. | [domain/mandala-cross.js](src/domain/mandala-cross.js) |
| Минута локального дня транзита → нужный образец пакета | Сопоставляет местный день с моментами UTC, включая изменение его длительности при переводе часов. Для дня рождения соответствующее правило находится в `domain/natal-day.js`. | [domain/day-timeline.js](src/domain/day-timeline.js), [domain/natal-day.js](src/domain/natal-day.js) |

У карты рождения есть Личность и Дизайн; у транзита — один набор активаций. Точные числа используются в расчётах, округление применяется к подписям. Процент внутри ворот или линии показывает положение на отрезке, а не выраженность качества человека.

В `astronomy.py` функция `longitudes()` получает положения планет. Пакеты шкалы дня берут их напрямую. Для отдельной карты `activations()` добавляет Землю, Южный узел, ворота и линии; при просмотре пакета дня эти сведения получает браузер из тех же положений.

Поиск момента Дизайна постепенно сужает промежуток времени. Если компьютер уже не может представить новое число между его границами, поиск заканчивается: повторять ту же проверку бессмысленно. Проверка точности результата остаётся обязательной.

## Что сохраняется и что кэшируется

**Сохранённая карта** нужна человеку и меняется по его действию. **Кэш** нужен для скорости: это данные, которые можно получить повторно.

- Библиотека карт записывается в браузер через [data/storage.js](src/data/storage.js). Это хранилище конкретного сайта и браузера, без серверной синхронизации библиотеки.
- Готовые пакеты транзита хранятся в ограниченном кэше памяти браузера; повторные открытия также используют HTTP-кэш. На сервере [services/transit-days.mjs](server/services/transit-days.mjs) управляет очередью, дисковым кэшем и подготовкой ближайших дней.
- Пакеты дня рождения получает [data/natal-day-client.js](src/data/natal-day-client.js). Они кэшируются в памяти и, если доступно, в IndexedDB через [natal-day-cache.js](src/data/natal-day-cache.js). Серверный [services/natal-days.mjs](server/services/natal-days.mjs) хранит такие результаты только ограниченное время в памяти.
- Устройство пакетов общее для сторон: [shared/day-packets/](shared/day-packets/). Сервер упаковывает их в [server/packets/](server/packets/), браузер проверяет и распаковывает перед использованием.

Готовый транзитный пакет можно отдать браузеру сразу. Его запись на диск остаётся в той же серверной очереди и не задерживает этот ответ. Очередь удерживает задачу до завершения записи, поэтому фоновые сохранения кэша не накапливаются. Остановка сервиса может дождаться окончания очереди.

Сервер узнаёт подходящий дисковый кэш по содержимому расчётного кода и файлов эфемерид. Время записи файла на диск на эту проверку не влияет. Изменились реальные данные или расчёт — нужен соответствующий им кэш.

Кэш пакета не сохраняет выбранную минуту, открытое меню или положение камеры. При открытии страницы сессия выбирает транзит; последняя открытая карта автоматически не восстанавливается. Поэтому «данные уже загружены» и «экран восстановлен после обновления страницы» — разные возможности.

## Локальный запуск

Нужны Node.js 24, Python и файлы из `data/`. В подготовленной копии достаточно `npm start`; сайт откроется на [127.0.0.1:4173](http://127.0.0.1:4173).

Для новой копии сначала создать окружение Python и установить зависимости:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm start
```

Обычный запуск читает исходники. Компактный вариант создаётся через `npm ci` и `npm run build`, затем запускается командой `npm run start:release`. [scripts/build-web.mjs](scripts/build-web.mjs) собирает его в `dist/`; содержимое этого каталога можно получить заново из исходников. Каждая страница заранее загружает только свои части: отдельная история `/love` не загружает приложение расчёта карты.
