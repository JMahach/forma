# Форма

Локальный сайт для расчёта и исследования бодиграфа. Дата, время и город рождения превращаются в активации ворот; схему можно приближать, перемещать и разбирать касанием. Код, движок расчёта и справочники лежат в этом проекте. Публичный хостинг не нужен.

Для разработки начните с [карты архитектуры](docs/ARCHITECTURE.md): что за что отвечает, где менять поведение и как проверять результат. Этот README описывает запуск и возможности. Инструкции для отдельного сервера находятся в [deploy/README.md](deploy/README.md); локальные изменения сами туда не отправляются.

## Проект за минуту

«Форма» состоит из трёх слоёв: браузер исследует готовую карту, Node обслуживает
запросы и управляет ограниченными очередями, Python выполняет астрономию.
Ни перемещение камеры, ни выбор ворот, ни движение по готовому дню не запускают
новый астрономический расчёт.

```text
Дата + время + город
        │
        ▼
Форма рождения → API Node → Python / Swiss Ephemeris
        ▲                         │
        └────── готовая карта ─────┘
                    │
          браузерная библиотека
                    │
           контроллер схемы ◄── клик / Shift / сводка
                    │
           состояние отрисовки
                    │
           SVG: схема + активации
                    │
        камера: масштаб и перемещение

Мандала: курсор → угол → четыре ворот → временная подсветка
Ползунок: пакет минут → выбранная минута → та же схема
```

В [архитектуре](docs/ARCHITECTURE.md) — полная карта модулей, порядок SVG-слоёв,
владение состоянием и маршруты изменения кода. Детали, которые стоит читать отдельно:

- [Дневной транзит](docs/TRANSIT_DAYS.md): местный день, UTC-пакеты, общий кэш.
- [Личный день](docs/CHART_DAYS.md): обе стороны карты, исторические зоны, временный просмотр.
- [Точность сжатия](docs/DAY_COMPRESSION.md) и [производительность мандалы](docs/HOVER_PERFORMANCE.md).
- [Выкладка и откат](deploy/README.md): отдельный сервис, ограничения VPS, проверки.

## Запуск на Mac / Linux

Проверенная среда: Node.js 24 и Python 3.9–3.12. В подготовленной копии проекта
окружение `.venv` уже установлено; для неё достаточно `npm start`. Для новой копии:

```sh
git clone https://github.com/JMahach/forma.git
cd forma
```

Репозиторий может требовать доступ вашего GitHub-аккаунта. Затем из его корня:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm start
```

Откройте [сайт на этом компьютере](http://127.0.0.1:4173). Npm-зависимостей нет, сборка фронтенда не требуется. Python-зависимости закреплены в `requirements.txt`: `pyswisseph==2.10.3.2` и `tzdata==2026.3`. Первая установка требует загрузки пакетов; последующие расчёты и поиск городов работают без внешних запросов.

Терминал с сервером оставьте открытым; остановка — `Ctrl+C`. JS и CSS отдаются
без сборки: после правки обновите страницу. При изменении серверных файлов или
списка публичных модулей перезапустите `npm start`.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Интерфейс, на котором слушает Node |
| `PORT` | `4173` | Порт, например `PORT=4174 npm start` |
| `TRANSIT_CACHE_DIR` | `.cache/transit/v1` внутри проекта | Только общий кэш транзита; на VPS отдельный доступный для записи каталог |

Если порт занят, остановите прежний экземпляр или выберите другой `PORT`.
Ошибка движка обычно означает отсутствующее `.venv` либо файлы из `data/`:
проверьте `npm run test:python`. Ошибка загрузки нового JS-модуля — повод проверить
его путь в `server/public-files.mjs`, а не открывать весь проект через HTTP.

Локально должны находиться `data/cities.json`, `data/ephe/sepl_18.se1` и `data/ephe/semo_18.se1`. Они включены в подготовленный проект. `.venv` не следует переносить между компьютерами — создайте окружение заново командами выше. Если для вашей версии Python нет готового пакета `pyswisseph`, установка может потребовать инструменты компиляции.

Для телефона или iPad в той же доверенной Wi-Fi-сети остановите обычный сервер и запустите:

```sh
HOST=0.0.0.0 npm start
```

На устройстве откройте `http://<локальный-IP-компьютера>:4173`. Компьютер должен оставаться включённым. Этот режим открывает сайт участникам локальной сети; по умолчанию сервер слушает только `127.0.0.1`. Регистрации, авторизации и HTTPS в самом Node-сервере нет. Публичное размещение на VPS — отдельная конфигурация из `deploy/`, не часть локального запуска.

## Создание и исследование карт

- **«Новая карта» в левом меню — карта рождения.** Введите имя, местные дату и время рождения, затем выберите город из списка. Можно вводить `12091990` и `1430`: разделители добавятся сами. Город определяет исторический часовой пояс, а не текущее смещение на вашем устройстве.
- **Перевод часов.** Для времени, которое повторялось дважды, появится выбор смещения. Несуществовавшее местное время не рассчитывается: нужно уточнить исходные данные.
- **«Транзит» — поминутный день.** Открывается при заходе на сайт. Сервер один раз готовит общий пакет UTC-дня и сохраняет его в кэше; браузер собирает из пакетов сегодняшний день в своём часовом поясе. Ползунок внизу показывает выбранную минуту без новых запросов и расчётов. «Сейчас» возвращает автоматическое обновление на границе минуты. Скрытая вкладка и форма рождения приостанавливают обновление; личная библиотека при прокрутке не перезаписывается. Масштаб схемы сохраняется. Устройство должно показывать правильные дату и время. Подробности — [дневной транзит](docs/TRANSIT_DAYS.md).
- **Кнопка с часами — день рождения по минутам.** У рассчитанной личной карты открывает ползунок внутри сохранённой местной даты. Пакет рассчитывается по запросу: в каждой минуте есть точные Личность и Дизайн. Загрузка сама не меняет исходную карту; движение ползунка показывает временный результат без новых запросов. «Исходное» и закрытие просмотра возвращают сохранённое время. Библиотека автоматически не изменяется. Смещения и повторное время учитываются по исторической зоне города. Подробности — [день рождения по минутам](docs/CHART_DAYS.md).
- **«Ввести вручную».** Позволяет записать известные активации без астрономического расчёта. В списке такие карты помечены как ручные. Встроенной демонстрационной карты в интерфейсе нет.
- **Значок меню слева.** Открывает библиотеку и создание карты. Рядом с именем каждой личной карты в библиотеке есть «⋯» → «Редактировать» / «Удалить». В верхнем заголовке схемы этого меню нет. Действия относятся к указанной карте, её не требуется предварительно открывать. У текущего момента меню отсутствует. Редактирование рассчитанной карты выполняет новый расчёт.
- **Удаление.** Нажмите «⋯» рядом с именем → «Удалить». После подтверждения карта удаляется безвозвратно. Новые копии для восстановления не создаются; если прежняя версия сохранила копию этой же карты, при удалении она тоже очищается. Восстановление, экспорт и импорт недоступны.

Схема содержит 9 центров, 64 ворот и 36 логических каналов. Подсветка показывает связи, полные каналы определяют центры. Выбор элемента только выделяет его, без всплывающей панели. Библиотека знаний открывается отдельно из левого меню, не сдвигая схему. Масштаб и положение сохраняются при переключении карт в текущем сеансе; кнопка с домиком возвращает всю схему в исходный вид. Для клавиатуры доступны Tab, Enter и пробел.

Нажатие на число активации в боковой колонке (например, `29.1`) открывает компактную подсказку с воротами, линией, цветом, тоном и базой. Процент — положение внутри соответствующего подразделения, а не степень выраженности свойства. Используется сохранённая долгота конкретной планеты; вручную заданным воротам такие данные не приписываются. Дробление на 6 линий, 6 цветов, 6 тонов и 5 баз описано в [материале Jovian Archive](https://jovianarchive.com/blogs/deeper-mechanics-system-theory/substructure-and-birth-time). Проценты округлены до двух знаков; для тонких подразделений особенно важна точность времени рождения. Подсказка закрывается повторным нажатием, нажатием вне неё или Escape. Выбор ворот и центров непосредственно на схеме по-прежнему не открывает окон.

Горло, сакрал и корень имеют одинаковые размеры. Цветовые семейства определённых центров соответствуют [традиционной схеме Jovian Archive](https://jovianarchive.com/blogs/human-design-basics/the-9-centers-in-human-design): голова и G — жёлтые, аджна — зелёная, эго и сакрал — красные, остальные — коричневые. Неопределённые центры белые. Конкретные оттенки подобраны для этого интерфейса; чёрные и красные активации каналов сохраняют отдельное обозначение личности и дизайна.

### Четыре переменные

В рассчитанных картах рождения между колонками и верхними центрами показаны четыре пары стрелок под заголовками «Цвет» и «Тон». Слева красные: сверху Sun/Earth дизайна (детерминация), снизу узлы дизайна (среда). Справа чёрные: сверху Sun/Earth личности (осознанность), снизу узлы личности (перспектива). Число цвета находится в контурной вертикальной стрелке: 1–3 — вниз, 4–6 — вверх. Число тона — в заполненной горизонтальной: 1–3 — влево, 4–6 — вправо. Цвет и тон вычисляются независимо из сохранённых долгот. Правила сверены с публичным клиентом [Maia Mechanics](https://app.maiamechanics.com/) и [описанием тонов Jovian Archive](https://jovianarchive.com/pages/the-basics-of-substructure-in-human-design); расположение четырёх пар — с [myBodyGraph](https://www.mybodygraph.com/blog/what-is-variable-in-human-design-understanding-the-arrows-in-your-chart).

Стрелки не показываются у транзита и ручных карт без долгот планет. Для неполных или противоречивых данных направления не придумываются: нужны обе записи каждой из четырёх пар с согласованными цветом и тоном. Существующие сохранённые расчёты читаются без миграции. Чистая логика находится в `src/activations/variables.js`, отдельная SVG-отрисовка — в `src/activations/variable-arrows.js`. Стрелки масштабируются вместе со схемой, не меняют её границы и не перехватывают нажатия.

## Как устроен расчёт

Движок — Swiss Ephemeris `2.10.03` через Python-обёртку `pyswisseph 2.10.3.2`. Используются локальные Swiss-файлы эфемерид; в заголовках включённых файлов указана база **JPL DE441**. Отсутствие нужных файлов завершает расчёт ошибкой: автоматический переход на приближённую модель Moshier запрещён.

Вычисляются тропические геоцентрические видимые долготы Солнца, Луны, планет и истинного северного узла (**true node**). Земля и южный узел берутся напротив Солнца и северного узла. Долготы сопоставляются с 64 воротами и шестью линиями. Для дизайна ищется момент до рождения, когда долгота Солнца отстаёт на 88°, а не просто дата за 88 суток. Для текущего момента вычисляется только один набор положений; натальный дизайн ему не приписывается.

В рассчитанной карте сохраняются исходные местные дата и время, выбранный город и его идентификатор, часовой пояс, UTC и смещение, выбор повторившегося времени, момент дизайна, долготы/ворота/линии для каждого объекта, версии движка и базы часовых поясов, а также численный остаток поиска 88°.

## Ограничения и проверка точности

Поддерживаются даты рождения **с 1801 по 2399 год включительно**, по григорианскому календарю. Это рабочий диапазон приложения, а не обещание одинаковой исторической достоверности для всех дат.

Часовые пояса берутся из закреплённого пакета IANA `tzdata 2026.3`, независимо от базы операционной системы. Сведения до 1970 года местами неполны, а будущие правила могут измениться. Для старых записей особенно важно проверить календарь, местные правила времени и точность самой записи рождения. Идентификатор часового пояса города не решает все исторические исключения. Подробнее — [ограничения базы IANA](https://data.iana.org/time-zones/tzdb/theory.html#accuracy).

Принята конвенция истинного, а не среднего лунного узла. Регрессионные проверки астрономического движка, границ ворот/линий и часовых поясов выполнены; один публичный пример из [проверочного набора DefinedSelf](https://definedself.com/data#verification-battery) совпал по всем 26 парам «ворота.линия». **Независимая проверка на официальных эталонах Jovian Archive и расширенном наборе карт ещё предстоит.** Значение `designArcResidualDegrees` характеризует сходимость численного поиска, а не общую точность карты и не достоверность исходного времени. Особенно чувствительны положения рядом с границами ворот и линий.

Автоматические тип и авторитет пока не выводятся. Профиль в сводке берётся из сохранённых линий Солнца Личности и Дизайна рассчитанной карты рождения. Пользовательская база знаний, синхронизация, регистрация и платежи не подключены. Описания — формулировки внутри системы Human Design, не медицинские или психологические заключения.

### Сводка «О карте»

Кнопка с книгой справа сверху открывает выдвижную панель, симметричную левому меню. Внутри — поиск и раскрываемые разделы: линии, центры, каналы и ворота. Панель накладывается на свободное пространство, не меняя геометрию, масштаб или положение камеры; прокручивается только её содержимое. Закрыть её можно той же кнопкой, нажатием снаружи или Escape. На узком экране обычный выбор закрывает панель и возвращает к схеме, а Shift сохраняет её открытой для составного выделения.

Для линий показаны отдельные количества Дизайна, Личности и общий итог. Считается каждая планетарная активация, в том числе оба узла и повторы одних ворот. Нажатие числа выделяет соответствующие ворота и точные строки активаций; Shift добавляет или снимает группу. В транзите показывается одна колонка. Для ручных карт количество линий не выдумывается.

Подсчёт отделён от интерфейса: `src/charts/chart-summary-data.js` читает сохранённые факты и существующую топологию. `src/charts/chart-summary-panel.js` содержит общий поиск, раскрытие, прокрутку и список `SUMMARY_SECTIONS`. Для нового раздела добавляются его данные, описание в этом списке и тесты; создавать ещё одну панель или менять SVG не требуется. Подробные описания, контуры, четверти и остальные категории из сайта-примера пока не перенесены.

## Подложка по силуэту бодиграфа

Светлая матовая подложка — самостоятельный цельный силуэт за бодиграфом, без тесной обводки каждого центра и узкой шеи. Плавный верх переходит в широкие плечи и округлый низ. Ровная наружная кайма построена обводкой одного контура, поверх которой лежит градиентная заливка с точно тем же путём: уменьшенной внутренней копии нет, толщина края не гуляет и он не заходит внутрь. Между подсветкой боковых каналов и каймой сохраняется дополнительный зазор. Колонки расчёта, стрелки и пространство вокруг мандалы не получают дополнительного фонового поля. Контур, палитра, ширина каймы и прозрачность собраны в `src/bodygraph/chart-backdrop.js`. Обычная подложка непрозрачна; только в мандале декоративная группа имеет непрозрачность 68%, чтобы сквозь неё мягко просматривались лучи. Каналы, центры, номера и выделения находятся вне этой группы и не становятся прозрачными. Слой не использует растровые изображения или blur-фильтры, не перехватывает события и не участвует в расчёте камеры. Для отключения подложки обычной схемы достаточно вернуть `showBackdrop: false` в `src/bodygraph/graph-controller.js`; подложка в мандале остаётся. По умолчанию SVG-рендерер обычный фон не добавляет: страница love остаётся прежней. Миниатюры сохранённых карт явно включают тот же силуэт; область SVG учитывает наружную кайму, чтобы не обрезать её. Размер миниатюры согласован с высотой имени и даты в карточке.

## Мандала

Переключатель «Мандала» справа сверху рядом с кнопкой «О карте» включает отдельный пастельный SVG-слой. Круг, схема и обе колонки сразу вписываются в доступный экран, без прокрутки страницы; масштабирование и панорамирование работают общей камерой. При выключении возвращается прежний вид схемы. Переключатель не изменяет карту и не требует нового расчёта.

Клик или касание кольца закрепляет **весь крест** в точной позиции нажатия: четыре ворот на кольце и бодиграфе и обе оси. Повтор снимает единственный выбранный крест; Shift добавляет или снимает крест независимо от других выделений. Общие ворота нескольких крестов не теряются при удалении одной группы. На самой схеме и в колонках сохраняется обычный выбор отдельных ворот; Shift позволяет вычесть ворота из креста, при этом оси неполного креста скрываются. Сохранённая карта не меняется. Порядок 64 секторов проверяется против расчётного движка. Луч каждой планеты и узла строится по сохранённой долготе и заканчивается точкой на внутреннем крае кольца; приблизительных лучей в середину ворот нет. Солнце и Земля выделены чуть сильнее, без смещения координат. Без полных проверяемых координат постоянные лучи не рисуются.

Наведение на кольцо отдельно показывает **крест под курсором**, а не меняет сохранённую карту. Точная угловая координата мыши задаёт Солнце личности; Земля противоположна, Солнце дизайна отстоит на −88°, его Земля тоже противоположна. Четыре ворот подсвечиваются на круге и схеме, чёрная и красная оси следуют за курсором. Профиль определяет правоугольную, джакстапозиционную или левоугольную категорию — это не отражение осей и не изменение знака 88°. Правила сверены с [официальным словарём Jovian Archive](https://jovianarchive.com/pages/human-design-dictionary). Каталог собственных названий крестов здесь не реализован. Наведение не делает сетевых запросов, не пересчитывает карту и не меняет закреплённый Shift-выбор. Уход мыши и масштабирование очищают только предпросмотр; смена карты сбрасывает также закрепление. С клавиатуры: фокус на воротах кольца, стрелки перемещают позицию, Escape скрывает предпросмотр; Enter закрепляет крест, Shift+Enter добавляет или снимает его. Перетаскивание и pinch не закрепляют крест.

Отрисовка: `src/bodygraph/mandala.js`; состояние режима и возврат камеры: `src/bodygraph/mandala-mode.js`; математика креста: `src/bodygraph/mandala-cross.js`; привязка к координатам указателя: `src/bodygraph/mandala-preview.js`. Текстовая подпись креста под курсором не показывается — остаются лучи и подсветка. Круг расширен на 5% относительно схемы; контраст кольца и границ ворот настроен отдельно от геометрии. В мандале блок «Цвет / Тон» целиком не отрисовывается: заголовки, стрелки и числа возвращаются при выключении режима. Колонки расчёта и номера ворот остаются. На узком телефоне это общий вид: для чтения мелких чисел доступно приближение; сенсорное перетаскивание сохраняет панорамирование, не имитируя мышиное наведение. В обычном режиме мандала не отрисовывается и прежняя геометрия не меняется.

Часы личного дня и переключатель мандалы стоят рядом справа. Домик появляется
слева от них только при приближении, не сдвигая остальные кнопки. Название и дата
остаются в шапке общего вида и скрываются при приближении; возврат домой показывает
их снова. Размытия холста нет. Ползунок транзита постоянно виден снизу, ползунок
личной карты открывается часами.

Закрепление вынесено в `src/selection/mandala-selection-state.js` поверх прежнего контроллера выделения. Точные углы сохраняются снимком, а схема получает обычные выбранные ворота. В режиме мандалы общая подложка помещается внутри масштабируемого силуэта через `src/bodygraph/mandala-underlay.js`: она смягчает фоновые лучи, позволяя им просматриваться сквозь свободное пространство внутри силуэта. Геометрия, цвета и области нажатия каналов и центров не меняются. За пределами силуэта прежние лучи остаются видны без изменений.

## Локальные данные и приватность

Браузер отправляет запрос города и данные для расчёта **серверу того адреса, на котором открыт сайт**. При локальном запуске это ваш компьютер, при открытии размещённой версии — VPS. Сервер читает собственные справочники и запускает Python-процесс; к сторонним калькуляторам данные не передаются. Он не записывает библиотеку карт на диск и не журналирует данные рождения. В проекте нет внешних шрифтов, аналитики или CDN. Начальная конфигурация VPS использует HTTP: передаваемые по нему данные не защищены TLS. Настройка HTTPS — отдельная задача, структурный рефакторинг её не выполняет.

Библиотека хранится в `localStorage` конкретного браузера и адреса сайта. На Mac и iPad, а также при открытии через разные адреса сервера это отдельные библиотеки. Очистка данных браузера удалит карты. Данные хранятся локально в читаемом виде, без шифрования; переноса и восстановления карт в интерфейсе нет.

Общий транзит не содержит личных данных. Его дневные пакеты сохраняются на сервере в `.cache/transit/v1/` и повторно используются браузерным HTTP-кэшем. Это не резервная копия личной библиотеки. Миниатюры личных карт рисуются из уже сохранённых активаций, без повторного астрономического расчёта.

Просмотр личного дня отправляет только дату рождения, идентификатор города и версию пакета через POST, без имени, примечания или ID карты. Сервер использует ограниченный кэш в RAM и не сохраняет личные дневные пакеты на диск. Браузер может держать до четырёх пакетов в IndexedDB, не больше 8 МиБ, со сроком повторного использования 30 дней и очисткой при последующих обращениях. Это отдельный локальный кэш без шифрования; удаление карты из библиотеки не удаляет пакет её даты и города. Полные правила и сроки — в [описании личных дней](docs/CHART_DAYS.md#ограничения-нагрузки-кэш-и-приватность).

Структура не декоративная: `tests/architecture.test.mjs` проверяет зависимости,
отсутствие циклов, достижимость браузерных модулей и точность публичного списка.
Тестовые стенды и исторические эталоны в `tests/` намеренно сохранены — они
защищают геометрию, Shift и точное восстановление минут, но не выдаются сайтом.

`npm start` запускает `server/server.mjs`. Сервер сохраняет адрес `http://127.0.0.1:4173` и API `/api/cities`, `/api/calculate`; дневной транзит доступен через `/api/transit/day?date=YYYY-MM-DD&v=1`, личный день — через `POST /api/chart/day`. Страница `public/index.html` доступна по `/` и `/index.html`, стили и значок — по `/styles.css` и `/favicon.svg`. Браузерные модули загружаются по своим путям `/src/...`.

Через HTTP доступен только явный список файлов из `public/` и `src/`. Сервер не выдаёт содержимое `server/`, `scripts/`, `data/`, `tests/`, Git, Python-окружения или произвольные файлы проекта. Новый браузерный модуль нужно явно добавить в `server/public-files.mjs`; сервер после изменения списка перезапускается. API-тест проходит полный граф импортов и проверяет, что ни один модуль не забыт.

## Ширина каналов и быстрый откат

В `src/bodygraph/bodygraph.js` параметр `CHANNEL_WIDTH_SCALE = 1.32` увеличивает ширину каналов на 32% от первоначальной: сначала +20%, затем ещё +10% от получившейся ширины. Для быстрого отката поставьте `1.2` (предыдущий шаг) или `1` (первоначальная ширина) и обновите страницу; сервер перезапускать не нужно. Вместе масштабируются цветные полосы, обводки и маски интеграции. Изгибы, центры, ворота, зоны нажатия и масштаб камеры от этого параметра не меняются. Регрессионный тест проверяет точное восстановление прежнего SVG при значении `1`.

## Тесты

```sh
npm test
npm run test:python
```

JavaScript-тесты проверяют топологию, SVG, жесты, даты, интерфейс и сохранение карт. Python-тесты — часовые пояса, неоднозначное и несуществующее время, диапазон дат, границы ворот/линий, расчёт дизайна и работу с реальными эфемеридами. Эти проверки не заменяют независимую валидацию полной Human Design-карты. Жесты на реальном iPad требуют проверки на устройстве.

Проверки HTTP API по умолчанию пропускаются. Чтобы включить их, сначала запустите `npm start`, затем в другом терминале выполните:

```sh
RUN_API_TESTS=1 npm test
```

Они обращаются только к локальному серверу и проверяют подсказки городов, расчёт, переходы времени и границы доступа к файлам. Другой адрес задаётся через `API_TEST_BASE_URL`.

Для движения креста есть отдельный [браузерный замер производительности](docs/HOVER_PERFORMANCE.md): одинаковая траектория, проверка совпадения SVG, сравнение полной и частичной отрисовки. Стенд использует синтетическую карту и не входит в публичную версию. Основной интерфейс объединяет движения по мандале в один кадр; частичный слой не меняет расчёт карты, Shift-выбор или частоту транзита.

Дневные ползунки опираются на отдельный [замер сжатия поминутных данных без потерь](docs/DAY_COMPRESSION.md). Сам исследовательский стенд использует реальные расчёты и проверяет обратное восстановление. Рабочие контракты, кэши и ограничения описаны отдельно для [транзита](docs/TRANSIT_DAYS.md) и [личного дня](docs/CHART_DAYS.md); размеры экспериментальных пакетов не заменяют замеры рабочих форматов.
