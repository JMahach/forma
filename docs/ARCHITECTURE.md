# Как устроена «Форма»

Это карта кода для человека, который хочет самостоятельно продолжить разработку.
Здесь описана текущая локальная версия, а не обещания будущих возможностей.

## Начните с трёх точек

1. `src/app.js` — собирает интерфейс из готовых контроллеров и соединяет их события.
2. `src/bodygraph/graph-controller.js` — применяет выбор и запускает перерисовку схемы.
3. `server/server.mjs` — запускает локальный сервер; Python остаётся отдельным процессом.

Фронтенд использует обычные браузерные ES-модули. Npm-зависимостей и сборщика нет.
Отдельный модуль нужен для самостоятельной ответственности, а не для каждой функции.
Модули подключаются явными импортами и параметрами; глобального диспетчера сервисов нет.

## Сервер: отдельные обязанности

`server/server.mjs` только загружает каталог, создаёт расчётчик и запускает HTTP.
Импорт остальных серверных модулей сам по себе не открывает порт и не запускает Python.

| Модуль | Ответственность |
| --- | --- |
| `server/app.mjs` | Маршруты, проверка запросов, HTTP-статусы и ограничение размера входа |
| `server/city-catalog.mjs` | Поиск, порядок подсказок и доверенные координаты города по идентификатору |
| `server/calculator-process.mjs` | Запуск Python для одиночного расчёта, его лимит процессов, таймаут и чтение результата |
| `server/transit-days.mjs` | Очередь дневных расчётов, ограниченный кэш в памяти/на диске, упаковка и HTTP-выдача |
| `server/transit_day.py` | Один запуск Python для всех минут UTC-дня; использует тот же калькулятор |
| `server/chart-days.mjs` | POST личного дня, доверенная зона города, один активный расчёт и три ожидающих, четыре готовых пакета только в RAM |
| `server/chart_day.py` | Все существующие местные минуты и оба fold; полный расчёт Личности и Дизайна на каждой минуте |
| `server/day-worker.mjs` | Общая граница пакетного Python: stdin/stdout, лимит байтов, таймаут, ожидание закрытия убитого процесса |
| `server/day-compression.mjs` | Общий выбор обратимых предикторов столбцов и упаковка Brotli/gzip; не знает HTTP и кэши |
| `server/content-encoding.mjs` | Чистое согласование Accept-Encoding; не зависит ни от транзита, ни от личной карты |
| `server/public-files.mjs` | Явный список публичных файлов и их выдача; остальные файлы закрыты |
| `server/calculator.py` | Сам астрономический расчёт и преобразование его результата |

## Два разных вида математики

**Астрономический расчёт** выполняет `server/calculator.py`: часовой пояс, UTC,
положения планет и поиск момента дизайна по солнечной дуге 88°. Swiss Ephemeris
и данные часовых поясов не перенесены в браузер.

**Математика отображения** выполняется в браузере. `domain/gate-wheel.js` переводит
уже известную долготу в ворота и линию. `bodygraph/mandala-cross.js` получает четыре
точки креста и категорию профиля для положения курсора. Это не новый расчёт рождения.
`mandala.js` рисует кольцо и лучи; `mandala-preview.js` переводит координаты мыши
через матрицу SVG в угол. `mandala-mode.js` меняет режим отображения; в основном
интерфейсе `homeFrame` всегда возвращает общий `STUDIO_FRAME` из `studio-layout.js`.
Рамка навигации с учётом раздвинутых колонок тоже одинакова для обоих режимов.
`mandala-motion.js` ведёт раскрытие кольца и движение колонок, а `gestures.js`
сохраняет точные положение и масштаб камеры при переключении.
Категория креста остаётся частью модели, но всплывающая текстовая подпись удалена.

## Как устроен сам рисунок

`graph-data.js` хранит исходные точки 9 центров, 64 ворот и 36 каналов.
Это топология, а не текущая карта. `drawing-geometry.js` один раз готовит кривые,
половины каналов, параллельные полосы и области отсечения. Геометрия интеграции
вынесена отдельно: несколько каналов используют общий ствол, но подсветка не
должна перетекать в соседнюю ветвь.

```text
public/index.html: #bodygraph (SVG, область жестов)
└─ #viewport (единственная матрица камеры)
   ├─ defs: градиенты и геометрические маски каналов
   ├─ mandala-scene: кольцо, сектора и лучи [по запросу, отдельный масштаб кольца]
   └─ bodygraph-drawing
      ├─ колонки активаций [в мандале — только при достаточной ширине]
      ├─ Цвет / Тон [только обычная схема]
      └─ центральный рисунок [одна геометрия; экранный масштаб задаёт камера]
         ├─ силуэт / полупрозрачная подложка
         ├─ каналы и подсветка интеграции
         ├─ центры
         └─ ворота: область нажатия, активация, выделение, число
```

`render-state.js` получает карту и закреплённый/временный выбор, строит производные
наборы. `bodygraph.js` собирает слои в этом порядке. Это чистая функция: одинаковые
входы дают одинаковую SVG-разметку. Камера не хранится в разметке, поэтому замена
минуты или выбор ворот не сбрасывают масштаб. Размер цифры не равен области нажатия.

Геометрические SVG-маски нужны для точной обводки каналов; это не отвергнутое
размытие интерфейса. Шапка и ползунки находятся снаружи SVG. `camera-controls.js`
показывает Домой при отклонении `x/y/k` от исходного вида. Шапка видна только
при 100% без смещения. `chart-heading-layout.js` измеряет полную ширину названия
и подписи и оставляет их по центру между кнопками, пока есть место; иначе опускает
под фактический нижний край кнопок. При открытой мандале опущенная подпись остаётся
видимой, если до верхней границы полного кольца есть не менее 8 CSS px; иначе CSS
скрывает её. Верхняя подпись остаётся видимой. Границу кольца предоставляет
`studio-layout.mandalaTop`, без влияния подписи на камеру. Скрытая через visibility
подпись сохраняет измеримость и возвращается при появлении места. Фиксированных
порогов ширины и отдельного выравнивания влево для коротких экранов нет.
Транзитная подпись показывает дату и минуту из `chart.utc` в зоне браузера,
в том числе при просмотре выбранной минуты. Колесо, pinch и кнопки используют одну камеру.

`computeStudioLayout()` получает размер canvas и CSS-отступы в экранных пикселях.
Единый квадратный `STUDIO_FRAME` содержит бодиграф, полное кольцо и внешнюю метку
курсора; `frame()` не зависит от режима или телефонного признака. Его масштаб
равен меньшему из доступных ширины и высоты, делённому на размер рамки. Сначала
вычисляется центр свободной области после отступов. По последнему правилу
вся композиция опускается на четверть зазора между нижней границей видимого
кольца и линией шкалы: `offsetY = max(0, (panel.y + 26 - ringBottom) / 4)`.
`gestures` получает этот сдвиг в экранных пикселях через `insets.offsetY` и
прибавляет его к обеим вертикальным границам области вписывания: размер области
и масштаб остаются прежними. Сдвиг одинаков с мандалой и без неё, независимо
от видимости шкалы. CSS задаёт
плавный верхний резерв от 64 до 112 px с учётом safe area и нижний
`max(64px, safe-area-inset-bottom + 60px)`. Боковые поля плавно меняются от 8 до
20 px с учётом safe area. Очень короткий экран ограничивает каждый вертикальный
отступ 49% высоты. Отступы постоянны относительно состояния панели: её показ,
скрытие, загрузка или ошибка не меняют исходный кадр.

Два блока расчёта (колонка и её «Цвет / Тон») используют общую геометрию
`activations/activation-layout.js`: равномерный масштаб 1.09 вокруг внутренних
краёв x=212/428 и y=76, затем подъём на 15.75 единицы, чтобы нижние цифры стояли
на уровне нижней границы подсветки ворот 41 (y=749.5 с обводкой). В обычном виде дополнительный отступ наружу равен 14
единицам и плавно исчезает при раскрытии мандалы. Масштабирование отделено
от движения колонок: прежний путь ±228 не увеличивается. Выравнивание
«Личности» измеряется в общей локальной системе заголовка и цифр.
Для колонок мандалы проверяется проекция общего `ACTIVATION_BLOCK_BOUNDS`
плюс путь каждой колонки на 228 единиц наружу, включая маркеры и области
нажатия. Высота увеличенных блоков меньше диаметра кольца. Если обе стороны не помещаются с зазором, `showMandalaColumns` становится
ложным и `getShowActivations` исключает колонки только в режиме мандалы. В обычном
режиме они остаются вертикальными столбцами; «Цвет / Тон» отсутствует в любой
мандале. Никакой альтернативной раскладки активаций по строкам нет.

Шкала всегда стоит снизу по центру, у нижнего края с учётом безопасного отступа.
Ширина видимой линии точно равна диаметру внешнего кольца мандалы в исходном виде,
без запаса под курсор: `2 * outerRadius * MANDALA_SCENE_SCALE * scale`.
Выключение мандалы и ручное приближение не меняют размер и положение шкалы.
Масштаб и базовые отступы исходного кадра сохранены; вертикальный сдвиг описан выше
и не зависит от видимости, загрузки или содержимого шкалы.
Координаты обеих `.day-controls` записывает `studio-layout`, даже когда одна
из панелей скрыта. В `app.js` ResizeObserver наблюдает только `#bodygraph`, а не
панели. Их состояние не может запустить пересчёт камеры.

Шкала перекрывает увеличенный рисунок только собственной небольшой плашкой:
нижняя полоса SVG не отсекается. Отдельное отсечение на `.canvas-wrap`
по-прежнему обслуживает боковые меню.

У шкал единый CSS на всех размерах: прозрачная область управления 48 px,
видимая плашка высотой 26 px со скруглением 8 px, native range и его невидимый
бегунок 44×44 px. Плашка выступает на 8 px за края линии и располагается в 9 px
от нижнего края на экране без системного безопасного отступа.
Вложенный `.day-range` с верхним отступом 4 px
расширен на 22 px за каждый край панели через отрицательный `margin-inline`.
Внутренняя `.day-reference-rail` отступает на те же 22 px: ход центра бегунка
и видимая линия совпадают с краями панели и кольца. Невидимую область за краем
узкого экрана ограничивает существующий `overflow: hidden` оболочки приложения, без прокрутки.
Исходная метка — контурное кольцо 18 px, семантически `button type="button"`.
Кнопка доступна с клавиатуры и для вспомогательных технологий, но прозрачна для
pointer-событий и не накрывает бегунок ещё одной зоной захвата. Подпись выбранного
времени проявляется через `:hover`/`:focus-within` в абсолютном слое, без изменения
высоты; ошибка и кнопка повтора занимают тот же постоянный слот. `aria-valuetext`
нативного range сохраняет дату, время и смещение.

`day-range.js` оставляет обычные `input` и клавиатуру нативному range. Только
pointerdown в пределах 22 px от метки начинает ожидание: короткий тап до 500 мс
с перемещением не более 8 px вызывает возврат на pointerup. Начавшийся drag меняет
минуту без предварительного возврата; при захвате возле бегунка сохраняется
смещение пальца относительно него. Притягивания к метке нет. Cancel, потеря захвата,
второй указатель, длинное нажатие и недоступное состояние не превращаются в возврат.
Обработчик не знает live-режима или исходной карты: контроллер транзита передаёт
`onNow`, контроллер личного дня — `explorer.reset()`, сохраняющий исходные секунды
и fold. `live-transit.state.referenceIndex` обновляется существующим минутным
циклом независимо от выбранной минуты; личная метка привязана к `original.utc`.

Приложение передаёт в `gestures` `getHomeFrame`: вписанный `STUDIO_FRAME` задаёт
минимальные 100%. `mandala-mode` всегда вызывает `refreshFrame()`, сохраняющий
точные `x/y/k`; никакого отдельного телефонного перехода камеры на переключении
нет. Расширенный `MANDALA_FRAME` используется как постоянная область навигации
в обоих режимах основного интерфейса. Resize сохраняет относительное приближение
к общему Home. Метод `transitionHome()` остаётся общей возможностью `gestures`,
но основной переключатель его не вызывает. Standalone-схемы без `getHomeFrame`
сохраняют собственное вписывание и пределы по активному кадру.

Телефонный признак по-прежнему определяется запросом `(max-width: 699px),
(pointer: coarse) and (max-width: 1099px) and (max-height: 500px)`, но используется
только для CSS-сдвига `.line-fixing { translate: -8px 0 }`.
Он не выбирает геометрию, масштаб, видимость колонок, подписи или место шкалы.

`mandala-motion.js` записывает два CSS-свойства в стабильный `#viewport`: прогресс
проявления кольца и смещение колонок. Один requestAnimationFrame-цикл существует
только во время перехода (200 мс), повторный клик разворачивает его. Полная замена
внутреннего SVG не сбрасывает прогресс. Режим и его интерактивность переключаются
сразу; выходящее кольцо остаётся только декоративным до одного финального render.
При reduced motion переход мгновенный. Математика и сохранённая карта не зависят
от анимации; кольцо использует opacity и небольшой scale, без blur. Камера на всех
экранах неподвижна при переключении. Там, где раздвинутые колонки не помещаются,
они проявляются обратно на обычных местах, без выезда из-за края экрана.

Автоматические и браузерные проверки размеров не заменяют проверку реального
iPhone; остальные сценарии устройства перечислены в `docs/MOBILE_REVIEW_PLAN.md`.
Для обычной ссылки во встроенном браузере Telegram добавлен
`ui/telegram-gestures.js`: пассивный `touchmove` только на SVG и двух range
отправляет `cancellingTouch` при наличии iOS-моста Telegram. Обработчик не меняет
DOM-события, камеру или прокрутку меню. Пользователь подтвердил перетаскивание
карты на iPhone; полный прогон pinch, шкал и системных жестов этим не подтверждён.
Механизм зависит от реализации клиента Telegram, а не от Mini App SDK;
источники и ограничения собраны в `docs/TELEGRAM_BROWSER.md`.

## Быстрый путь мандалы

`mandala-preview-painter.js` обновляет только движущиеся лучи, точки и указатель,
пока четыре ворота, карта и закреплённый выбор не изменились. На переходе ворот
контроллер использует полную отрисовку, чтобы подсветка каналов и колонок осталась
точно такой же. Это небольшой безопасный быстрый путь, не второй SVG-рендерер.
При смене карты, выбора, режима или совпадении с закреплённым крестом действуют
проверки сброса кэша. Чистый `renderBodygraph` остаётся эталоном всей разметки.

`hover-preview` объединяет движения курсора по мандале в одно обновление на кадр.
Само положение записывается сразу: клик всегда использует последнюю точку, даже
если кадр ещё не нарисован. Уход курсора и очистка отменяют ожидающий кадр;
клавиатура и обычные наведения не откладываются. Частота транзита не связана с этим.

Таблица ворот существует и в Python, и в JavaScript; тесты проверяют их совпадение.
Граница интервала относится к следующей линии/воротам. Не округляйте долготу
перед расчётом: это уничтожит узкие переходы. Округление допустимо только для текста.
Проценты цвета/тона/базы вычисляются отдельно в `activation-details.js`; сохранённые
ворота остаются авторитетными данными, а не заменяются догадкой отрисовщика.

## Кто владеет состоянием

- `chart-store` — сохранённые карты и идентификатор выбранной карты. Контроллеры не ведут свои копии коллекции.
- `live-transit` — временная карта выбранной минуты и режим «Сейчас». `app.js` подставляет её вместо сохранённой записи транзита; прокрутка ничего не сохраняет.
- `chart-day-explorer` — исходная личная карта и временный результат выбранной минуты. Загрузка сохраняет исходный расчёт до движения ползунка; закрытие, смена карты и форма возвращают его. Хранилище карт не вызывается.
- `day-range` — только незавершённый жест возле исходной метки; выбранная минута и действие возврата принадлежат контроллеру соответствующего дня.
- `selection-state` — обычный выбор; `summary-selection-state` добавляет независимые группы линий;
  `mandala-selection-state` добавляет владение воротами креста. Нижние уровни не импортируют верхние.
- `selection-targets` — общие правила того, какие ворота принадлежат выбранному элементу.
- `hover-preview` — временный предпросмотр. Он не заменяет закреплённый выбор.
- `gestures` — камера; `mandala-mode` — переключение её представления.
- `studio-layout` — производная компоновка из размеров canvas и постоянных отступов; показ панели не является входом расчёта.
- `birth-form`, `chart-library`, `live-transit`, `chart-day-explorer` — только собственное временное состояние интерфейса/запросов.

Рендерер получает снимок состояния и возвращает разметку. Ни одна отрисовка
не должна сохранять карту, запускать сеть или менять другой контроллер.

## Типовые маршруты

```text
Создание карты:
форма → API → сервер → Python → результат → хранилище карт → схема

Дневной транзит:
Python (все минуты UTC-дня) → кодек → общий дисковый кэш → HTTP-кэш браузера
местный день + ползунок → минута готового пакета → временная карта → схема

Личный день:
кнопка → кэш браузера / POST дата+cityId+версия → доверенная зона города
Python (все местные минуты, P+D) → FCD1 → ограниченный RAM сервера → браузер
ползунок → временная карта с прежним ID → схема; исходная метка → сохранённая карта

Выделение:
клик / Shift / клавиатура → контроллер выбора → снимок состояния → SVG + сводка

Мандала:
курсор → угол → предпросмотр креста → подсветка
клик → закрепление креста; уход курсора очищает только предпросмотр
```

`public/styles.css` — один каскад с именованными секциями компонентов; базовые
правила не дублируются, адаптивность, reduced-motion и печать собраны в конце.
Не переносите CSS-правила между секциями без проверки приоритетов, мобильного вида
и печати. Отдельный SVG задаёт собственные цвета, размеры и области взаимодействия.

## Проверки перед завершением изменения

1. `npm test` — чистые функции, контроллеры, SVG и сохранение поведения.
2. `npm run test:python` — астрономия, часовые пояса и границы расчёта.
3. С запущенным локальным сервером: `RUN_API_TESTS=1 npm test` — API и полный граф загрузки браузерных модулей.
4. Открыть браузер: сохранённая карта и транзит, обычный вид и мандала, клик/Shift,
   сводка, изменение масштаба, форма, личный день с возвратом к исходному и узкий экран.
   Зелёные тесты не заменяют этот шаг.

`tests/architecture.test.mjs` автоматически проверяет, что браузерные модули
достижимы от настоящих точек входа, граф импортов не содержит циклов, доменная
математика не зависит от интерфейса, а личный день не импортирует сервис транзита.
Новый файл получает собственную обязанность и тест; ради красивого дерева не
создаются пустые фасады или папки с единственной переадресацией.

`tests/previews/` содержит синтетические визуальные стенды, а не мусор.
`tests/fixtures/selection-before-refactor.js` — независимый исторический эталон
поведения. Не переписывайте его под новый код и не удаляйте ради уменьшения проекта.
Снимки прежней геометрии защищают форму каналов; отдельная проверка подтверждает
намеренное уменьшение цифр. Не обновляйте эталон просто потому, что тест упал.

`tests/benchmarks/` — отдельный браузерный стенд производительности с синтетической
картой. Он не входит в публичный список файлов и не читает библиотеку пользователя.
Сравнение сначала проверяет равенство SVG, затем запускает одинаковые
траектории. Подробности и ограничения замеров описаны в `docs/HOVER_PERFORMANCE.md`.

## Границы текущей архитектуры

Одиночный расчёт рождения по-прежнему запускает отдельный Python; его лимит —
четыре одновременных процесса. У дневного транзита своя очередь с одним активным
пакетным расчётом. У личного дня — ещё одна очередь с одним активным и тремя
ожидающими расчётами. Это отдельные лимиты, не общий пул. Готовые дни повторно
используются без Python; постоянный Python-процесс пока не внедрён.

Транзит сохраняется в общем дисковом кэше и публичном HTTP-кэше. Личный день
возвращается с `private, no-store`: сервер сохраняет только четыре пакета в RAM
на 10 минут повторного использования, с проверкой срока при обращении, без
таймера удаления. Браузер отдельно хранит до четырёх пакетов в IndexedDB
(8 МиБ, 30 дней, очистка при чтении/записи). Дата и город не равнозначны имени
или библиотеке: дневной API не принимает личную коллекцию и не сохраняет её.
Контракты, версии, точность и измерения — в [дневном транзите](TRANSIT_DAYS.md)
и [личном дне](CHART_DAYS.md).

Библиотека остаётся в браузере конкретного адреса. Нет аккаунтов, синхронизации,
экспорта или резервных копий. Локальная версия не равна развёрнутой; публикация,
HTTPS, вопросы лицензирования и оптимизация VPS — отдельные задачи.
