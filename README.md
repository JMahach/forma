# Форма

«Форма» превращает дату, время и город рождения в интерактивную схему Human Design. Можно рассматривать связи, приближать рисунок, выбирать ворота и исследовать каждую минуту дня. Расчёт и справочник городов работают локально; публичный сервер для запуска не нужен.

Этот README — единая карта проекта: **что считается, где это лежит и как части связаны**. Инструкции по запуску, проверкам и серверу находятся здесь же. Отдельно сохранены только [уведомления о сторонних компонентах](THIRD_PARTY.md) и [исходные лицензии](licenses/).

## Как всё связано

| Часть | Простыми словами | Работа |
| --- | --- | --- |
| Браузер | Альбом и пульт | Показывает карту, хранит библиотеку, обрабатывает выбор, жесты и минуту дня |
| Node | Приёмная | Принимает запросы, находит город, управляет очередями и отдаёт результат |
| Python | Калькулятор | Переводит местное время в UTC и рассчитывает положения на небесном круге |

```text
Дата + время + город → форма → API Node → Python / Swiss Ephemeris
                                 ↑                 │
                                 └── готовая карта ┘
                                           │
                           библиотека → выбранная карта → SVG
                                                            ↑
Ползунок → готовый пакет дня → временная минута ──────────────┤
Клик / Shift → выбранные элементы → подсветка ────────────────┤
Перетаскивание / pinch → камера → масштаб и положение ────────┘
```

Перетаскивание рисунка не запускает Python. Нажатие на ворота меняет выделение. Ползунок уже загруженного дня выбирает готовую минуту. Серверный расчёт нужен для новой карты или отсутствующего пакета дня.

## Где какая математика

| Что считаем | Простое объяснение | Файл |
| --- | --- | --- |

| Сводка и профиль | Считаем сохранённые активации, читаем линии Солнца обеих сторон | [chart-facts.js](src/domain/chart-facts.js) |
| Фиксация линии | Сопоставляем активации с таблицей правил | [line-fixing.js](src/domain/line-fixing.js), [line-fixing-data.js](src/domain/line-fixing-data.js) |
| Крест мандалы | Готовая долгота → четыре точки и ворота креста; указатель сначала переводится в угол | [mandala-cross.js](src/domain/mandala-cross.js), [mandala-preview.js](src/scene/mandala-preview.js) |
| Минута дня → карта | Читаем уже рассчитанные долготы из пакета, восстанавливаем активации | [transit-day.js](src/domain/transit-day.js), [natal-day.js](src/domain/natal-day.js), [day-timeline.js](src/domain/day-timeline.js) |

У рождения две стороны: Личность в момент рождения и Дизайн в найденный более ранний момент. У транзита один набор без натального Дизайна. Процент внутри ворот, линии или подразделения означает **положение на отрезке**, а не выраженность качества человека. Округлённая подпись не участвует в расчёте.

**Каждое пришедшее событие `input` шкалы обрабатывается по порядку.** Ускорение уменьшает стоимость обновления, сохраняя промежуточное движение активаций. Здесь нет отбрасывания минут до последнего значения кадра. Отдельное объединение hover-событий мандалы и анимация переключения режима не меняют этот контракт.

Временный просмотр минуты не перезаписывает сохранённую карту. Модульная перестройка не добавляет новые гарантии хранения: конфликты вкладок, миграция и восстановление библиотеки в этот этап не входили.

## Запуск на Mac / Linux

В рабочей копии 28 сентября 2026 года проверены Node.js **24.18.1** и Python **3.9.6**. Для новой копии:

```sh
git clone https://github.com/JMahach/forma.git
cd forma
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm start
```

Репозиторий может требовать доступ GitHub. Для подготовленной копии достаточно `npm start`. Откройте [127.0.0.1:4173](http://127.0.0.1:4173); остановка — `Ctrl+C`. Npm-зависимостей и сборки фронтенда нет. Python-зависимости закреплены в [requirements.txt](requirements.txt): `pyswisseph==2.10.3.2`, `tzdata==2026.3`.

Нужны `data/cities.json`, `data/ephe/sepl_18.se1`, `data/ephe/semo_18.se1`; они входят в подготовленный проект. Первая установка загружает Python-пакеты, последующие расчёты и поиск городов работают без внешних запросов. `.venv` создают заново на каждом компьютере; при отсутствии готового пакета `pyswisseph` могут понадобиться инструменты компиляции.

| Настройка | По умолчанию | Зачем |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Интерфейс Node |
| `PORT` | `4173` | Другой порт: `PORT=4174 npm start` |
| `TRANSIT_CACHE_DIR` | `.cache/transit/v1` внутри проекта | Дисковый кэш общего транзита |

После правки JS/CSS обновите страницу. После изменения сервера или списка публичных файлов перезапустите `npm start`. При ошибке движка проверьте `.venv`, данные и `npm run test:python`; при недоступности нового JS-модуля — [server/http/public-files.mjs](server/http/public-files.mjs).

Для телефона в той же доверенной Wi-Fi-сети запустите `HOST=0.0.0.0 npm start` и откройте `http://<локальный-IP-компьютера>:4173`. Компьютер должен оставаться включённым. Это доступ для локальной сети; авторизации и HTTPS в самом Node нет. Публичный сервер настраивается отдельно по разделу ниже.

<summary>Интерфейс: карты, выделение, сводка и активации</summary>

Ввести дату, местное время и город рождения, получить карту и исследовать её связи. Доступны также ручной ввод известных ворот, текущий транзит и просмотр дня рождения по минутам. На схеме 9 центров, 64 ворот и 36 логических каналов.

| Действие | Результат |
| --- | --- |
| «Новая карта» в левом меню | Форма рождения; город выбирает исторический часовой пояс |
| «Ввести вручную» | Карта известных ворот без астрономического расчёта |
| «Транзит» | Сегодняшний местный день; кольцевая метка возвращает режим «Сейчас» |
| Часы у рассчитанной личной карты | Временный просмотр обеих сторон карты для выбранной минуты дня рождения |
| «⋯» у карты в библиотеке | Редактирование или удаление именно этой записи |
| «О карте» | Сводка с поиском по линиям, центрам, каналам и воротам |
| «Мандала» | Кольцо с точными планетными лучами и выбором крестов |
| Домик | Возврат масштаба и положения к общему исходному виду |

Ползунок использует готовый пакет минут без нового запроса на каждое движение. Личный просмотр не должен перезаписывать исходную карту: закрытие или короткое нажатие на метку рождения возвращает исходный расчёт, включая секунды. Ввод новой записи и временное исследование минуты — разные действия. Исправление сохранения в текущий рефакторинг не входило.

Перемещение, приближение и выделение не запускают астрономию. При переводе часов назад форма предлагает выбор повторившегося времени; несуществовавшее местное время отклоняется. У ручной карты без исходных долгот не выдумываются планетные подробности, линии или переменные.

### Выделение, мандала и управление с клавиатуры

Нажатие на ворота, канал или центр выделяет элемент. Shift добавляет или снимает элементы. Само выделение схемы не открывает справочное окно: библиотека знаний вызывается отдельно из левого меню. Для управления доступны Tab, Enter и пробел.

Нажатие на кольцо мандалы закрепляет крест в точной позиции: четыре ворот и две оси. Повтор снимает единственный выбранный крест; Shift позволяет добавить или убрать крест независимо от других групп. Общие ворота нескольких крестов сохраняются, пока нужны хотя бы одной группе. Из креста можно вычесть отдельные ворота через Shift; оси неполного креста скрываются.

Наведение — отдельный временный предпросмотр. Уход указателя или изменение масштаба убирает предпросмотр; смена карты сбрасывает также закреплённые кресты. Перетаскивание и pinch не превращаются в нажатие на крест. На воротах кольца стрелки клавиатуры меняют позицию, Enter закрепляет крест, Shift+Enter добавляет/снимает его, Escape скрывает предпросмотр. Каталог собственных названий крестов не реализован; всплывающая текстовая подпись креста не показывается.

Постоянные лучи берутся из сохранённых долгот планет и узлов. При отсутствии проверяемых координат они не подменяются приблизительными лучами в середину ворот. Колонки в мандале показываются только там, где помещается их полная геометрия; блок «Цвет / Тон» в мандале скрыт. Переключение сохраняет камеру и не меняет исходную карту.

Код: `src/selection/` хранит выбор; `src/domain/mandala-cross.js` считает крест; `src/scene/mandala-preview.js` связывает его с указателем; `src/scene/mandala.js` рисует кольцо, `src/scene/modes/mandala.js` управляет режимом.

### Сводка «О карте» и точные строки активаций

Правая панель содержит поиск и раскрываемые разделы: линии, центры, каналы, ворота. Она накладывается на интерфейс и не меняет камеру; прокручивается содержимое панели. Закрытие — кнопкой панели, нажатием снаружи или Escape. На узком экране обычный выбор закрывает панель, а Shift оставляет её открытой для составного выделения.

Для линий отдельно показаны Дизайн, Личность и сумма. **Каждая планетная активация считается отдельно**, включая оба узла и повторения одних ворот. Две планеты в одинаковых воротах — две записи в счётчике, но одни ворота на рисунке. Нажатие счётчика выбирает связанные ворота и точные строки соответствующей стороны/линии; Shift добавляет или снимает группу. Транзит имеет одну колонку. Для ручной карты без нужных данных количества линий не придумываются.

Профиль рассчитанной карты берётся из сохранённых линий Солнца Личности и Дизайна. Автоматические тип и авторитет пока не выводятся. Расширенные описания, контуры, четверти и полная пользовательская база знаний не добавлены.

Данные: `src/domain/chart-facts.js` извлекает факты и топологию, `src/views/chart-summary-data.js` добавляет названия. Интерфейс: `src/views/chart-summary-panel.js`; список `SUMMARY_SECTIONS` задаёт разделы. Новый раздел требует своих данных и представления, а не второй панели или нового расчёта планет.

### Подробности активации, четыре переменные и фиксации линий

Нажатие на число в колонке, например `29.1`, открывает ворота, линию, цвет, тон и базу. Процент означает положение долготы внутри подразделения, а не силу свойства человека; подпись округлена до двух знаков. Источник — сохранённая долгота конкретной активации. Повторное нажатие, нажатие снаружи или Escape закрывает подсказку.

Математика подразделений находится в `src/domain/substructure.js`. `src/views/activation-details.js` только готовит подписи результата, `src/views/activation-popover.js` управляет подсказкой.

Четыре пары стрелок рассчитанной карты разделены по сторонам: слева Дизайн — Sun/Earth сверху и узлы снизу; справа Личность — Sun/Earth сверху и узлы снизу. Цвет 1–3 направлен вниз, 4–6 вверх; тон 1–3 — влево, 4–6 — вправо. Цвет и тон вычисляются независимо. Нужны все четыре согласованные пары: пропуски, дубли и противоречия не дополняются догадками. У транзита и ручной карты натальные переменные не выводятся. Правила — `src/domain/variables.js`, рисунок — `src/scene/variable-arrows.js`.

Знаки возле активации показывают **экзальтацию**, **падение** или их сочетание. Это применение справочной таблицы к предоставленной карте, без изменения долготы или исходных данных. Планета, указанная правилом, должна находиться в тех же воротах или непосредственно гармонических воротах. У карты рождения учитываются обе стороны; у транзита только его реальные активации. Текущие транзиты не добавляются к личной карте автоматически. Узлы могут иметь фиксированную линию, но сами не фиксируют чужую.

Таблица — `src/domain/line-fixing-data.js`, правило — `src/domain/line-fixing.js`, знаки — `src/scene/activation-columns.js`. Источник таблицы SharpAstrology.HumanDesign 1.2.0 и MIT-уведомление сохранены в [THIRD_PARTY.md](THIRD_PARTY.md) и [licenses/](licenses/). Все 384 линии записаны явно; пустая запись не означает универсальное отсутствие свойства. Проверки переноса таблицы не являются официальной сертификацией трактовок Human Design.

<summary>Точность: календарь, астрономия, подразделения и ограничения</summary>

Поддерживаются даты рождения **1801–2399 включительно**, по григорианскому календарю. Местное время проверяется по закреплённой IANA `tzdata 2026.3`, независимо от базы ОС. Повторённое время требует выбора `fold`; несуществовавшее отклоняется. Исторические смещения могут включать секунды. Данные до 1970 года местами неполны, будущие правила могут измениться: город и зона не гарантируют достоверность исторической записи рождения.

Swiss Ephemeris `2.10.03` через `pyswisseph 2.10.3.2` считает **тропические геоцентрические видимые долготы** и **истинный Северный узел**. В заголовках локальных файлов эфемерид указана база JPL DE441. Отсутствие нужных файлов завершает расчёт ошибкой; скрытый переход на приближённую модель Moshier запрещён.

Поиск Дизайна идёт двоичным делением интервала 75–100 суток до рождения, 48 шагов. Проверяется остаток солнечной дуги не более `1e-7°`. Это критерий сходимости решателя, а не общая погрешность карты или достоверность времени рождения. Долготы Дизайна вычисляются в найденный момент; округлённая текстовая метка времени не используется для повторного расчёта.

Колесо начинается с ворот 41 на долготе **302°**. Для долготы `λ` берётся смещение `(λ − 302°) mod 360°`, сектор шириной `5,625°` и линия шириной `0,9375°`. Границы полуоткрытые: левая входит, правая относится к следующему сектору. При углублении в цвет/тон/базу поправляется только численный шум у внутренней границы; проценты и подписи заранее не округляются. Сохранённые ворота не заменяются новым предположением по одной подписи.

С картой сохраняются местные дата/время, город и ID, зона, UTC и смещение, выбор повторённого времени, момент Дизайна, долготы/ворота/линии, версии движка/tzdata и остаток поиска 88°. Профиль читается из линий Солнца Личности и Дизайна. Автоматические тип и авторитет, аккаунты, синхронизация и платежи не подключены.

В прежней проверке один пример DefinedSelf совпал по всем 26 парам «ворота.линия». Независимая проверка долгот и расширенного набора карт по официальным эталонам Jovian Archive ещё не выполнена. Особенно чувствительны положения у границ. Описания Human Design — формулировки внутри этой системы, не медицинские или психологические заключения.

</details>

**Владельцы состояния.** Коллекция карт — `src/data/chart-store.js`; открытая карта — `src/state/chart-session.js`; временная минута — `src/state/live-transit.js` или `src/state/natal-day.js`; закреплённый выбор — `src/selection/selection-model.js`; временное наведение — `src/selection/hover-preview.js`. `src/app.js` соединяет их callback-функциями. Рендереры хранят только DOM-ссылки и кэши, не запускают сеть и не сохраняют карту.

```text
Размер canvas + CSS → layout → исходный кадр, место колонок и шкал
Жест → camera → transform единственного #viewport
Шкала → состояние дня → chart-session → updates → renderer → узлы SVG
Выбор / наведение → selection → updates → производное выделение → SVG
```

**Геометрия рисунка.** Исходная форма задана в SVG-пространстве 640 × 820: 9 центров, 64 ворот, 36 каналов. Кривые, половины каналов и отсечения готовятся заранее и не зависят от карты. Камера меняет только матрицу `#viewport`; координаты центров и ворот не подгоняются под телефон. Размер цифры и область нажатия — отдельные параметры.

**Общий Home.** Квадратный `STUDIO_FRAME` содержит полное кольцо и внешнюю метку курсора. `studio-controller.frame()` возвращает его в обоих режимах и на всех экранах. Историческое имя `PHONE_MANDALA_FRAME`, на которое ссылается `STUDIO_FRAME`, не вводит отдельное телефонное правило. Расширенный `MANDALA_FRAME` служит постоянной областью навигации в обоих режимах основного интерфейса.

**Вписывание и вертикальный сдвиг.** После постоянных отступов масштаб равен меньшей из доступных ширины и высоты, делённой на ширину общей рамки. Композиция центрируется в свободной области и опускается на четверть положительного зазора между низом кольца и линией шкалы: `offsetY = max(0, (panel.y + 26 - ringBottom) / 4)`. `ringBottom` берётся до сдвига. `computeCameraFit()` переносит одинаковый сдвиг на обе вертикальные границы вписывания; размер области и масштаб остаются прежними.

**Отступы экрана.** CSS задаёт верхний резерв от 64 до 112 px с учётом safe area, нижний `max(64px, safe-area-inset-bottom + 60px)`, боковые поля от 8 до 20 px с учётом safe area. Очень короткий экран ограничивает каждый вертикальный отступ 49% высоты. Показ, скрытие, загрузка, ошибка и текст шкалы не меняют исходный кадр. Наблюдатель основной компоновки в `app.js` следит за `#bodygraph`, а не за панелями.

**Камера.** Колесо, pinch, drag, клавиатура и кнопки обращаются к одной камере. Home — минимальные 100%; на этом масштабе рисунок не уходит от исходного положения. Переключение мандалы вызывает `refreshFrame()` и сохраняет точные `x/y/k`. Resize сохраняет относительное приближение к Home. `transitionHome()` остаётся отдельной возможностью камеры, которую основной переключатель не вызывает. Схемы вне основного интерфейса без `getHomeFrame` используют собственное вписывание.

**Мандала.** Радиусы, центр, сектора и лучи задаёт `mandala-geometry.js`. Отдельный `MANDALA_SCENE_SCALE = 1 / .84` сохраняет утверждённую пропорцию кольца и тела; тело при переключении не уменьшается. Ориентация колеса: 0° слева, 90° снизу, 180° справа, 270° сверху. Это геометрия отображения. Перевод долготы в ворота и линии находится в `src/domain/gate-wheel.js`, четыре точки креста — в `src/domain/mandala-cross.js`, цвет/тон/база — в `src/domain/substructure.js`; астрономические положения рассчитывает серверный Python.

**Колонки.** `activation-layout.js` увеличивает колонки и «Цвет / Тон» в 1.09 раза вокруг внутренних краёв x=212/428 и y=76, затем поднимает на 15.75 единицы. Нижние числа выровнены по нижней границе подсветки ворот 41. Обычный дополнительный отступ наружу 14 единиц задаёт CSS; он плавно исчезает при раскрытии мандалы. Путь раздвижения каждой колонки на 228 единиц расположен снаружи масштабирования и не увеличивается вместе с блоком.

**Видимость колонок.** `layout.js` проецирует `ACTIVATION_BLOCK_BOUNDS` вместе с путём раздвижения и проверяет зазор 8 CSS px с обеих сторон. Границы включают фиксации и области нажатия. Если места нет, колонки скрываются только в мандале; при выходе проявляются на обычных местах, без выезда из-за края. В обычной схеме сохраняются вертикальные столбцы; раскладки по строкам нет. «Цвет / Тон» в мандале отсутствует. `src/scene/activation-columns.js` выравнивает заголовок «Личность» и числа в общей локальной системе координат.

**Подпись.** [chart-heading-layout.js](src/views/chart-heading-layout.js) измеряет текст и фактическое место между кнопками. Подпись всегда по центру; если не помещается, опускается ниже кнопок. В мандале такая нижняя подпись видна при зазоре не менее 8 CSS px до полного кольца; верхняя остаётся видимой. Скрытие через `visibility` сохраняет измеримость. Размер сцены от текста не зависит. `camera-controls.js` показывает подпись только в Home, а кнопку «Домой» — при отклонении `x/y/k`. [chart-display.js](src/views/chart-display.js) берёт транзитную дату и минуту из показанного `chart.utc`.

**Положение шкал.** `studio-controller.js` записывает координаты обеих панелей, включая скрытую. Они снизу по центру; длина линии равна `2 × outerRadius × MANDALA_SCENE_SCALE × scale` исходного вида, без запаса под курсор. Выключение кольца и ручное приближение не меняют длину или положение шкалы. Плашка перекрывает только собственную площадь, без отсечения нижней полосы увеличенного SVG. Отдельное отсечение оболочки обслуживает боковые меню.

**Устройство шкалы.** Общий CSS сохраняет прозрачную область 48 px, плашку 26 px и невидимый нативный бегунок 44 × 44 px. `.day-range` расширен на 22 px с каждой стороны, `.day-reference-rail` отступает на те же 22 px: видимая линия и ход центра бегунка совпадают. Кольцевая метка 18 px — семантическая кнопка, доступная с клавиатуры и прозрачная для pointer-событий. Время появляется при наведении или фокусе; ошибка и повтор занимают постоянный слот, без изменения высоты.

**Тап возле метки.** [views/day-range.js](src/views/day-range.js) оставляет обычный drag и клавиатуру нативному range. В пределах 22 px от метки короткий тап до 500 мс и не более 8 px движения возвращает исходный момент только на отпускании. Начавшийся drag меняет минуту без предварительного возврата и притягивания; при захвате возле бегунка сохраняется смещение пальца. Cancel, потеря захвата, второй указатель, длинное нажатие и отключённая шкала не вызывают возврат. Транзит возвращается к «Сейчас», личный день — к сохранённым секундам и fold. Это действие отдельно от Home камеры.

**Каждое изменение минуты.** Каждый доставленный допустимый ввод рабочей шкалы обрабатывается сразу, каждое изменение минуты проходит через состояние к отображению. Разные минуты нельзя объединять в «последнее значение кадра», откладывать debounce или пропускать ради FPS. Повтор уже показанной минуты не требует повторной отрисовки. Долготы обновляются и при неизменных воротах/линиях. Отдельное ожидание тапа возле метки обслуживает `day-range.js`; как только жест признан перетаскиванием, значения передаются контроллеру дня напрямую.

**Переход режима.** `mandala-motion.js` хранит проявление кольца и смещение колонок в двух CSS-свойствах постоянного `#viewport`. Один rAF-цикл работает только во время перехода до 200 мс. Повторный клик разворачивает движение с текущего положения; reduced motion завершает его сразу. Уходящее кольцо немедленно теряет интерактивность и удаляется после завершения. Используются opacity и небольшой scale, без blur; камера неподвижна.

**Телефон и Telegram.** Телефонный media query в `studio-controller.js` влияет только на CSS-сдвиг `.line-fixing` к числам, а не на масштаб, колонки, подпись или шкалу. [ui/telegram-gestures.js](src/ui/telegram-gestures.js) отправляет `cancellingTouch` через доступный iOS-мост на пассивном `touchmove` SVG и двух шкал. Он не отменяет DOM-события, не управляет камерой и не перехватывает меню. Это обычный браузер Telegram, без Mini App SDK. Подтверждение перетаскивания карты на iPhone не означает полного испытания pinch, шкал и системных жестов.

**Постоянная сцена.** [bodygraph-svg.js](src/scene/bodygraph-svg.js) остаётся чистым эталоном полной разметки. `renderer.js` создаёт каркас и далее вызывает painters. Смена `interactive`, `idPrefix` или `showLabels` пересоздаёт каркас; смена минуты или выбора сама по себе этого не требует. При смене декоративного режима нужный слой добавляется/удаляется, а существующие каналы, центры и ворота перемещаются между группами. Их области нажатия сохраняются. `#viewport` и его камера остаются снаружи этого обновления.

**Изменяемые фрагменты и маски.** `bodygraph-painter.js` отдельно обновляет полосы каналов и содержимое небольших масок интеграции. Общий ствол принадлежит нескольким маршрутам: отсечения удерживают обводку на принадлежащих выбранному маршруту ветвях. Это геометрические SVG-маски, а не размытие интерфейса. `mandala-painter.js` сохраняет сектора и лучи; маленький слой креста перестраивается при смене упорядоченной четвёрки `source:planet:gate`, внутри неё меняются атрибуты. `activation-painter.js` сохраняет цели планет и чисел, обновляя нужную строку или колонку.

**Короткий путь предпросмотра.** [mandala-preview.js](src/scene/mandala-preview.js) переводит указатель через обратную SVG-матрицу в угол. [mandala-preview-painter.js](src/scene/mandala-preview-painter.js) двигает только лучи, точки и курсор, пока прежними остаются карта, выбор и четвёрка ворот. Смена контекста или совпадение с закреплённым крестом возвращает обычное обновление через постоянный renderer; это больше не означает замену всего SVG. Обычный mandala painter сверяется с фактическими атрибутами и восстанавливает их после внешнего быстрого предпросмотра. При пересоздании содержимого прежнего wheel нужен его `reset()`.

**rAF применяется к наведению, не к шкалам.** `selection/hover-preview.js` объединяет движения указателя по кольцу в один кадр, но записывает точку сразу: клик использует последнее положение. Уход и очистка отменяют ожидающий кадр; клавиатура и обычные наведения не откладываются. Этот механизм нельзя переносить на ввод дневных шкал.

**Точность и декорации.** Перед определением ворот, линий и подструктуры долготу не округляют: граница относится к следующему интервалу. Округление SVG-координат и текста выполняется при отображении. Сохранённые ворота не заменяются догадкой renderer. Лотос остаётся экспериментальным декоративным силуэтом; [backdrop.js](src/scene/backdrop.js), [mandala-underlay.js](src/scene/mandala-underlay.js) и контуры в `scene/geometry/` не меняют центры, каналы, ворота или рамки камеры. Прозрачность подложки в мандале не распространяется на лежащие поверх каналы, числа и выделение.

**Ширина каналов и откат.** Единственный `CHANNEL_WIDTH_SCALE = 1.32` теперь находится в [src/scene/bodygraph-paint.js](src/scene/bodygraph-paint.js): сначала ×1.2, затем ещё ×1.1, всего +32%. Для предыдущего шага поставьте `1.2`, для исходной ширины — `1`, затем обновите страницу; перезапуск сервера не нужен. Вместе меняются полосы, их смещения, обводки, ореол и маски интеграции. Кривые, центры, ворота, самостоятельные области нажатия и камера не меняются. [tests/channel-width.test.mjs](tests/channel-width.test.mjs) проверяет точное восстановление исторического полного SVG при `1`.

**Что сохранять при дальнейших изменениях.** Сцена, шкалы, подписи и столбцы — утверждённое поведение. Реорганизация модулей сама по себе не является основанием менять их вид. Исторические геометрические эталоны нельзя переписывать лишь потому, что тест обнаружил различие. После изменения этих правил проверяются оба режима, сохранённая карта и транзит, обе шкалы, Home, resize, клик/Shift, клавиатура и сохранение фокуса. Автоматические размеры и браузерные стенды не заменяют проверку жестов на реальном телефоне.

</details>

### Одиночный расчёт и поиск городов

`GET /api/cities?q=Москва` ищет город от двух символов и возвращает до 12 подсказок. `POST /api/calculate` принимает JSON до 20 000 байт и возвращает `{ "chart": ... }`. Пример тела рождения:

```json
{ "mode": "natal", "name": "Тестовая карта", "date": "1990-06-15", "time": "14:30", "cityId": "524901", "cityName": "Москва" }
```

Сервер доверяет зоне из своего каталога. При `ambiguous_time` ответ содержит `choices`; повторный запрос передаёт числовой `fold: 0` или `fold: 1`. Несуществующее время отклоняется. Одиночный `mode: "transit"` также поддерживается. JSON-ответы имеют `no-store`. Если передан `Origin`, проверяется его host относительно `Host`; это не авторизация.

### Два вида дня

Транзит — общий день положений планет. Личный день — изменение времени рождения в пределах выбранной
местной даты, с отдельным расчётом Личности и Дизайна в каждой минуте. Это не наложение транзита на
неподвижную личную карту.

Python считает день одним процессом; Node упаковывает числа; браузер загружает пакет и выбирает
готовую минуту. Движение ползунка не запускает новый запрос или астрономический расчёт. Серверный
упаковщик браузером не импортируется.

| Свойство | Транзит | Личный день |
| --- | --- | --- |
| API | `GET /api/transit/day?date=YYYY-MM-DD&v=1`; также HEAD | `POST /api/chart/day`; GET/HEAD → 405 |
| Вход | Сегодня UTC ±2 суток; `v` можно опустить | JSON до 1024 байт; точная дата 1801–2399, строковый `cityId`, обязательная версия |
| Формат | FTD1, `TRANSIT_DAY_VERSION = '1'` | FCD1, `CHART_DAY_VERSION = '1'` |
| Владелец | `shared/day-packets/transit-format.js` | `shared/day-packets/natal-format.js` |
| Календарь | Ровно 1440 UTC-минут с полуночи | 1–2880 существовавших местных минут |
| Значений на минуту | 11 исходных долгот Float64 | 11 долгот Личности + 11 Дизайна + UTC-секунды Дизайна + остаток дуги |
| Заголовок | До 4096 байт | До 16 384 байт, до 128 временных сегментов |
| HTTP-сжатие | Brotli 11 или gzip 9 | Brotli 9 или gzip 9 |
| HTTP-кэш | С текущей `v`: `public, max-age=31536000, immutable`; без `v`: `no-cache`; ETag/304 | `private, no-store`; без ETag и публичного immutable-кэша |

Тело запроса личного дня:

```json
{ "birthDate": "1990-06-15", "cityId": "524901", "v": "1" }
```

Часовой пояс берётся из серверного каталога по `cityId`; присланный timezone или объект города его
не заменяет. В дневной Python-процесс передаются только дата и доверенная зона — без имени,
примечания, ID карты и библиотеки. Дата рождения и город не записываются в URL. Некорректные дата,
город или версия не запускают расчёт; действует общая проверка Origin/Host.

Ответы — `application/octet-stream`. По `Accept-Encoding` сервер выбирает Brotli, gzip или несжатые
байты; используется `Vary: Accept-Encoding`. Запрет всех поддерживаемых вариантов даёт 406. Ошибки
возвращаются JSON и не кэшируются. Старый одиночный `/api/calculate` с `mode: transit` остаётся API;
текущий браузерный транзит использует дневные пакеты.

### Точность и устройство пакета

Оба формата начинаются с четырёх байтов `FTD1`/`FCD1`, затем четырёхбайтовой little-endian длины JSON-заголовка, самого заголовка и числовых столбцов. Заголовок описывает версию,
сетку, движок, эфемериды, tzdata, истинный узел, тропический геоцентрический видимый зодиак и
порядок предиктора каждого столбца.

Независимые долготы: Солнце, Луна, Северный узел, Меркурий, Венера, Марс, Юпитер, Сатурн, Уран,
Нептун, Плутон. Земля и Южный узел выводятся из противоположных долгот теми же операциями, что в
калькуляторе. Ворота и линии восстанавливаются общими правилами. Порядок столбцов закреплён
форматом, а не порядком значков интерфейса.

`shared/day-packets/float64-codec.js` применяет предикторы 0–4 к **64-битным представлениям чисел**.
Модульная разность, zigzag и перестановка байтов обратимы. `server/packets/compression.mjs` выбирает
порядок отдельно для каждого столбца пробным Brotli 4, затем сжимает весь пакет. Округления,
квантования и интерполяции долгот нет. Браузер снимает HTTP-сжатие; `decode.js` проверяет версию,
длины, метаданные, размеры, временные сегменты и диапазоны чисел.

Рабочий FCD1 хранит `designArcResidualDegrees` отдельным 24-м столбцом. `designUtc` имеет ту же
точность до секунд, что одиночный API, но активации Дизайна рассчитаны на исходном моменте решателя
**до** преобразования в текст. Нельзя получать их из округлённого `designUtc` или заменять Солнце
Дизайна арифметическим «Солнце Личности минус 88°».

«Без потерь» относится к записанным минутным точкам. Промежуточные секунды не передаются. Совпадение
с движком не подтверждает точность исходного времени рождения, всей астрономической модели или
интерпретаций Human Design.

### Местное время и просмотр

Серверный транзитный кэш хранит UTC-дни и не размножается по городам. `src/domain/day-timeline.js`
собирает сегодняшний местный день через браузерный Intl/IANA: обычно нужны два UTC-пакета, иногда
три. Местный день нельзя считать фиксированными 24 часами; повторные часы различаются подписью
UTC-смещения. Эта календарная база зависит от браузера/ОС и не подменяет Python tzdata рождения.

Для личного дня `server/python/civil_time.py` проверяет оба `fold` каждой местной метки
`00:00`–`23:59` по закреплённой tzdata. Пропущенные минуты исключаются, повторные сохраняются и
сортируются по UTC. Возможны 1380/1500 минут при часовом переходе, 1410/1470 при получасовом и 2880
при повторении целой даты. Отсутствующая полночь допустима; пропущенная целая дата возвращает
`nonexistent_date`.

Сегмент `{index, startUtc, offsetSeconds, utcOffset, fold}` описывает участок последовательных
минут. Исторические смещения могут содержать секунды: Париж 01.01.1900 начинается в
`1899-12-31T23:50:39Z`, смещение `UTC+00:09:21`. Между соседними сегментами не обязательно ровно 60
UTC-секунд. Браузер читает эти серверные сегменты; начальный индекс выбирает по сохранённому UTC и
fold.

Личный день загружается только после открытия часов у рассчитанной карты с датой, городом и
корректным UTC. До движения ползунка виден исходный расчёт, включая секунды. Предпросмотр сохраняет
имя, ID, примечание и служебные даты; библиотека не перезаписывается. «Исходное», закрытие
просмотра, смена карты и открытие формы возвращают исходную запись. Камера и закреплённый выбор
сохраняются. Отмена не позволяет позднему ответу вернуть прежний предпросмотр.

«Сейчас» у транзита следует часам устройства; скрытая вкладка, открытая форма и другая карта
приостанавливают публикацию. При ошибках действует задержка повторов.

### Кэши и нагрузка

| Участок | Настройки по умолчанию |
| --- | --- |
| Одиночный расчёт | Допуск до 4 работ; Python timeout 15 с |
| Серверный транзит | 1 активная + до 5 ожидающих; Python timeout 60 с, вывод до 500 000 байт |
| Серверный личный день | 1 активная + до 3 ожидающих; Python timeout 30 с, вывод до 2 000 000 байт |
| Готовый транзит на сервере | До 7 дней в RAM и до 7 файлов текущего отпечатка на диске |
| Готовый личный день на сервере | До 4 пакетов в RAM, срок повторного использования 10 минут; без диска и прогрева |
| Транзит в браузере | До 4 декодированных дней в RAM, HTTP-кэш; timeout 20 с |
| Личный день в браузере | До 3 декодированных дней в RAM; timeout сети 60 с |
| IndexedDB личных пакетов | `bodygraph-chart-days`: до 4 пакетов, суммарно 8 МиБ, срок 30 дней от записи |

Лимиты трёх сервисов независимы; постоянного Python-worker и единого глобального лимита нет. Таймаут
Python не включает очередь и упаковку; каждый принятый запрос не обязательно успеет до срока
браузера/nginx. Дневная очередь ждёт фактического закрытия остановленного процесса. Бюджет CPU/RAM
VPS проверяется под нагрузкой.

Одинаковые запросы объединяются: транзит по UTC-дате, личный день на сервере по дате и доверенной
зоне. При запуске и после полуночи UTC прогреваются сегодня и завтра. Транзитный gzip сохраняется
атомарно как `YYYY-MM-DD.<16-значный-fingerprint>.gz` в `.cache/transit/v1` либо
`TRANSIT_CACHE_DIR`. Корректный файл после перезапуска используется без Python, повреждённый
пересчитывается. Ошибка диска не отменяет готовый ответ из RAM.

Fingerprint учитывает код/контракты и состояние эфемерид — размер и mtime. Перенос кода в нынешние
модули вызывает пересчёт прежнего дискового кэша, не меняя FTD1. **При изменении эфемерид, флагов,
вычислительных правил или восстановления поднять соответствующую версию в `transit-format.js` /
`natal-format.js`; изменение tzdata личной сетки требует новой CHART_DAY_VERSION.** Дисковый
fingerprint не отменяет старый immutable-ответ в браузере.

Личные RAM-пакеты очищаются по сроку при следующем обращении, не таймером. IndexedDB удаляет
истёкшую запись при чтении и очищает коллекцию при новой записи. Это сроки использования, не
обещание физического удаления в точную минуту. Перезапуск сервера очищает личный RAM-кэш; постоянной
серверной библиотеки нет.

Ключ IndexedDB содержит версию, дату и ID города, без имени, примечания и ID карты. Хранятся байты
**после** HTTP-распаковки, а не маленький Brotli-пакет. Блокировка/переполнение базы не мешает
загрузке; ошибка фоновой записи не отменяет готовый день. Кэш привязан к браузеру и адресу, не
шифруется и не служит резервной копией. Браузер может удалить его раньше. Удаление карты не очищает
общий пакет её даты/города; очистка данных сайта удаляет библиотеку и локальные кэши.

КБ = 1000 байт; длинный день выходит за обычный диапазон. Это выборка, не верхняя граница и не
доказательство предельного сжатия. Эксперимент восстанавливает остаток дуги из двух Солнц; рабочий

Экспериментальный генератор проверяет исторические секунды и повторные часы, но не пропущенные
целые даты и переходы в полночь; рабочий личный API их обрабатывает. Стенд не предназначен для
публичной обработки пакетов и не реализует API, кэш или ползунок.

### Как обновляется экран

1. [scene/updates.js](src/scene/updates.js) получает текущую карту и выбор. Сводка обновляется при изменении значимых для неё данных; поповер — при изменении карты.
2. [renderer.js](src/scene/renderer.js) создаёт SVG-каркас при первом показе и сохраняет его между минутами. [bodygraph-painter.js](src/scene/bodygraph-painter.js), [activation-painter.js](src/scene/activation-painter.js) и [mandala-painter.js](src/scene/mandala-painter.js) меняют существующие узлы и атрибуты.
3. Полный монтаж остаётся для нового каркаса, изменения его структурных параметров и повторного показа после очистки. Декоративные группы и изменившиеся небольшие фрагменты могут добавляться или удаляться. «Постоянная сцена» не означает полного запрета любых DOM-операций.
4. При движении внутри той же четвёрки ворот [mandala-preview-painter.js](src/scene/mandala-preview-painter.js) двигает только точные отметки предпросмотра. При изменении условий используется обычное обновление. Предметная математика общая для обоих путей.
5. [views/library.js](src/views/library.js) сохраняет строки меню при выборе карты. Закрытая библиотека не создаёт миниатюры. Для открытой изображения готовятся только возле видимой области, порциями до четырёх; сами строки при первом открытии пока создаются для всей коллекции.
6. [views/thumbnail.js](src/views/thumbnail.js) вызывает общий `renderBodygraph` с `profile: 'thumbnail'`. Профиль исключает невидимые в миниатюре ворота, подсветку, области взаимодействия и относящиеся к ним определения. Видимая геометрия берётся из того же renderer. Кэш содержит до 100 результатов по наборам активаций, без имени и данных рождения.

Строковый [bodygraph-svg.js](src/scene/bodygraph-svg.js) нужен для первого монтажа, миниатюр, отдельной страницы и эталонного сравнения. [bodygraph-paint.js](src/scene/bodygraph-paint.js) хранит общие правила оформления, чтобы строковый и адресный пути не расходились. Профиль миниатюры явно отделён от обычного `interactive: false`: статический SVG тоже может нуждаться в подсветке.

### Замер обновления сцены — 28 сентября 2026

Сравнивались опубликованный renderer коммита `5a5c6258ae826b9de9d9eb340c341ded3cc13fc3` и постоянная сцена рабочей копии на одинаковой синтетической последовательности карт. ### Проверки телефона и обычной ссылки Telegram

Узкое окно настольного браузера проверяет компоновку, но не заменяет устройство. После изменений нужны портрет/альбомная ориентация, safe area, крайние маркеры, шкалы и их исходные метки, pinch, движение в четырёх направлениях, прокрутка панелей и пользовательская оценка читаемости.

Выкладывается проверенный Git-коммит; локальная работа не меняет прод. Обновление «Формы»

| Что | Где / как |
| --- | --- |
| Адреса конфигурации | `http://89.125.202.66/`, `r840525.s1698.vm.mydomain.zone`; рассказ `/love` |
| Релиз | `/opt/forma/current` → `/opt/forma/releases/<короткий-SHA>` |
| Node | `/opt/forma/node/bin/node`, версия 24 |
| Python | `.venv` релиза указывает на сохраняемое серверное окружение |
| Приложение | `forma.service`, пользователь `forma`, только `127.0.0.1:4173` |

`deploy/forma.service`: 400 МиБ RAM, 50% одного CPU, 32 задачи. `ProtectSystem=strict` оставляет
релиз только для чтения; `CacheDirectory=forma` с правами `0700` разрешает постоянную запись общего

По HTTP выдаётся явный список `server/http/public-files.mjs`: `public`, `src` и разрешённые

браузерный модуль добавляется в allowlist; после изменения списка Node перезапускается.

### Подготовка и публикация

1. Выполнить JavaScript-, Python- и включённые HTTP-проверки из основного раздела
   README с локальным сайтом на 4173, затем `git diff --check`. В браузере проверить
   транзит, личную карту, ползунки, обычный вид/мандалу, Shift, Домой, обе панели
   и телефонный размер. Закоммитить и отправить обычным `git push`, без force.
   `.venv`, `.cache`, `.env`, личные карты, скриншоты и SSH-пароли в Git не добавлять.
2. Упаковать ровно проверенный коммит:

   ```sh
   git archive --format=tar.gz --output=/tmp/forma-release.tar.gz HEAD
   git rev-parse HEAD
   ```

3. На VPS прочитать `systemctl status forma`, `systemctl cat forma`, свободное
   место, текущую цель `current` и статус VPN-контейнера. Сохранить прежние unit
   и nginx-конфигурации отдельно в каталоге резервной версии.
4. Передать архив по SSH и распаковать в **новый** `/opt/forma/releases/<SHA>`,
   не поверх работающего каталога. Владелец кода — root; `forma` имеет чтение.

5. Подключить серверное `.venv`, проверить закреплённые `requirements.txt`.

6. От `forma` выполнить серверные тесты нового каталога и реальные Python-расчёты

   сервер рядом с продом на маленьком VPS.
7. Сохранить предыдущий релиз; переключить `current` на новый, установить
