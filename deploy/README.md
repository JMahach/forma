# Публикация «Формы» и откат

Локальная разработка не меняет прод. Выкладывается конкретный проверенный Git-коммит,
а не произвольное содержимое рабочего каталога. VPN живёт отдельно: обновление
«Формы» не перезапускает Docker, не меняет VPN, firewall, SSH или его ключи.

## Устройство VPS

| Что | Где / как |
| --- | --- |
| Публичный сайт | `http://89.125.202.66/`, рассказ — `/love` |
| Текущий релиз | `/opt/forma/current` → каталог в `/opt/forma/releases/` |
| Исходники релиза | `/opt/forma/releases/<короткий-SHA>` |
| Node | `/opt/forma/node/bin/node`, версия 24 |
| Python | `.venv` внутри релиза указывает на сохраняемое серверное окружение |
| Приложение | `forma.service`, пользователь `forma`, только `127.0.0.1:4173` |
| Обратный прокси | nginx, `/etc/nginx/conf.d/forma.conf` |
| Общий кэш транзита | `/var/cache/forma/transit/v1`, создаётся через `CacheDirectory=forma` |
| Данные пользователя | Библиотека карт остаётся в браузере; личные дни — ограниченный RAM-кэш сервера |

`forma.service` ограничивает приложение 400 МиБ RAM, 50% одного CPU и 32 задачами.
`ProtectSystem=strict` оставляет файлы релиза доступными только для чтения;
systemd разрешает запись лишь в собственный каталог кэша. Python не является
постоянным worker: одиночные и дневные расчёты запускают отдельные процессы.
Общий транзит готовится при запуске и на границе UTC-дня, затем переиспользуется.

nginx ограничивает частоту API-запросов и соединения. API ожидает ответ до 65 с,
поскольку холодный дневной расчёт может быть дольше обычной карты. Браузер имеет
свои сроки ожидания: 20 с для транзита и 60 с для личного дня. Переполненная или
долгая очередь может дать повторяемую ошибку; число запросов не снимает лимиты.
Обычный запуск заранее прогревает сегодняшний и завтрашний транзит.

## Перед выкладкой

Из корня репозитория, с локальным сайтом на 4173:

```sh
npm test
npm run test:python
RUN_API_TESTS=1 npm test
git diff --check
```

В браузере проверить транзит, личную карту, ползунки, обычный вид и мандалу,
Shift, Домой, обе панели и телефонный размер. Затем закоммитить и отправить
изменения обычным `git push` без force. Не добавлять `.venv`, `.cache`, `.env`,
личные карты, скриншоты или SSH-пароли в Git.

Пакет должен содержать ровно коммит:

```sh
git archive --format=tar.gz --output=/tmp/forma-release.tar.gz HEAD
git rev-parse HEAD
```

В архиве есть код, тесты, документация, справочник городов и эфемериды, но нет
`.git` и локального Python-окружения. Приложение по HTTP выдаёт только явный список
`server/public-files.mjs`, не весь каталог релиза.

## Порядок обновления

1. Прочитать `systemctl status forma`, `systemctl cat forma`, свободное место,
   текущую цель `current` и статус контейнера VPN. Сохранить исходные конфигурации
   сервиса и nginx отдельно в каталоге резервной версии.
2. Передать архив по SSH и распаковать в **новый** `/opt/forma/releases/<SHA>`.
   Не распаковывать поверх работающего приложения. Владелец кода — root,
   чтение доступно пользователю `forma`.
3. Подключить серверное `.venv` и проверить pinned-зависимости из `requirements.txt`.
   Окружение macOS на Linux не переносить. Если зависимости поменялись, подготовить
   отдельное новое окружение до переключения; прежнее оставить для отката.
4. До переключения запустить от `forma` серверные тесты нового каталога и реальные
   Python-расчёты. Проверять с ограничением CPU/RAM, не создавать второй постоянно
   работающий сервер рядом с продом на маленьком VPS.
5. Сохранить предыдущий релиз. Переключить `current` на новый, установить
   `deploy/forma.service` и `deploy/forma.nginx`, выполнить `nginx -t`.
   При первой миграции, когда `current` ещё обычный каталог, сначала остановить
   только `forma`, переименовать каталог в резервный и создать ссылку.
6. `systemctl daemon-reload`, `systemctl restart forma`, затем
   `systemctl reload nginx`. Не перезапускать весь сервер.
7. Выполнить проверки ниже. Старый релиз и конфигурации пока не удалять.

## Что подтвердить после

- `/` и `/love` возвращают 200; браузер действительно загрузил новый интерфейс.
- `/api/cities?q=Moscow` работает; одиночный синтетический расчёт возвращает карту.
- `/api/transit/day?date=<сегодня-UTC>&v=1` возвращает декодируемый пакет FTD1,
  повторный запрос использует тот же ETag, файлы кэша появились в `/var/cache/forma`.
- `POST /api/chart/day` с синтетическими датой, `cityId` и `v:"1"` возвращает FCD1,
  `Cache-Control: private, no-store`; все минуты читаются браузером.
- `systemctl show forma -p MemoryCurrent -p TasksCurrent -p NRestarts` не показывает
  цикл перезапусков; `systemctl is-active forma nginx` — `active`.
- VPN-контейнер остался запущен и не перезапускался.

Один ответ nginx 200 не доказывает готовность расчётного API. Проверки рождения
выполнять на синтетических данных, не на личной библиотеке.

## Откат

Остановить только `forma`, вернуть `current` на сохранённый предыдущий каталог,
восстановить сохранённые конфигурации systemd/nginx, проверить `nginx -t`, затем
`systemctl daemon-reload`, `systemctl start forma`, `systemctl reload nginx`.
Повторить HTTP/API-проверки. Не удалять неудачный релиз до разбора причины.
Кэш транзита восстановим; браузерные карты при таком откате не перезаписываются.

## Границы публикации

Сейчас используется HTTP, не HTTPS: данные рождения в сети не защищены TLS.
HTTPS и авторизация — отдельные работы. Пароли сервера сюда не записываются.
Лицензия собственного кода не назначается этой инструкцией; требования Swiss
Ephemeris и `pyswisseph` описаны в [THIRD_PARTY.md](../THIRD_PARTY.md). Приватность
репозитория сама по себе не решает вопрос лицензирования публичного сервиса.
